Upload, list, and delete your app's stored objects, and read access or runtime logs within your plan's retention window. Runtime lines take time to appear, and static Spaces have no runtime logs.

Every command here takes the global flags (`--api-url`, `--profile`, `--token`, `-y`/`--yes`, `--json`) and the space selection flags (`--space`, `-o`/`--team`, `--claim-token`). See [the CLI overview](/cli).

## sf storage

List object metadata and quota usage for files uploaded by a Space's app.

This is runtime object storage, not your published files. Only a Space with a runtime app has any. Objects are addressed by a bare 32-character hex id. There is no key or path.

```text
sf storage [target] [--space <value>] [--limit <n>] [--cursor <value>]
```

`sf storage ls` is the same command with the same flags, aliased as `sf storage list`.

### Arguments

| Argument | What it is |
| --- | --- |
| `[target]` | Space ID, slug, live URL, or domain. Defaults to the linked Space |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--limit=<n>` | `50` | Maximum objects to return. Maximum 100 |
| `--cursor=<value>` | none | Continue from the opaque cursor returned by the last page |

```bash
sf storage
sf storage docs --limit 10
sf storage ls --space docs
```

### Output

A table of `Id | Size | Type | Uploaded by | Created`, or "No stored objects." A further page prints as `Next cursor: <value>`.

With `--json`, `data` is `{ objects, cursor }`. Each object carries `id`, `contentType`, `createdAt`, `filename`, `size`, `uploaderId`, `sha256`, and `url`.

Upload with [`sf storage put`](#sf-storage-put) or the API.

### Errors

| Code | Exit | When |
| --- | --- | --- |
| `validation_error` | 2 | `--limit` or `--cursor` did not parse. Raised before the request |

## sf storage put

Upload one file to the Space's app storage.

```text
sf storage put <file> [--space <value>] [--content-type <value>] [--public]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `<file>` | Path to a regular file. Required. 5 MiB at most |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--content-type=<value>` | `application/octet-stream` | The object's MIME type |
| `--public` | `false` | Make the object readable by anyone holding its URL |

The file's base name becomes the object's `filename`. Without `--public` the object is private, and the public read URL never serves it. The same content policy as any upload applies, so active web content and executables are refused. See [Storage](/object-storage#limits).

```bash
sf storage put receipt.pdf --content-type application/pdf
sf storage put logo.png --content-type image/png --public --space docs
```

### Output

`Uploaded <file>: <id> (<size> B).` With `--json`, `data` is the stored object.

### Errors

| Code | Exit | When |
| --- | --- | --- |
| `validation_error` | 2 | The path is not a regular file, or the file is larger than 5 MiB. Raised before the request |

## sf storage rm

Force-delete an app storage object as the Space owner, regardless of who uploaded it. Aliased as `sf storage remove` and `sf storage delete`.

```text
sf storage rm [id] [--space <value>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `[id]` | Object id, for example `0123456789abcdef0123456789abcdef` |

No command-specific flags.

The id must be the 32-character hex id `sf storage` lists. A path-shaped value is rejected. This is a destructive remote action, so it prompts unless you pass `-y`. Delete is idempotent: an already-gone object prints "`<id>` was already gone."

```bash
sf storage rm 0123456789abcdef0123456789abcdef --yes
```

### Output

With `--json`, `data` carries `deleted`.

## sf logs

Read a Space's logs.

`access` is every request the edge served. `runtime` is what your code logged, with the request id and handler for each line. A static Space has no runtime lines.

A line you just triggered takes a while to appear — it's written on the origin, shipped, and indexed before it can be read back. **An empty page means not yet, not broken.** Keep paging while the cursor is there: a page can come back empty while there's still more to read.

```text
sf logs [target] [kind] [--space <value>] [--limit <n>] [-f] [--cursor <value>]
  [--request-id <value>] [--handler <value>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `[target]` | Space ID, slug, live URL, or domain. Defaults to the linked Space |
| `[kind]` | `access` or `runtime`. Defaults to `access` |

A bare kind in the first slot works: `sf logs runtime` is the same as `sf logs --space <linked> runtime`.

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--limit=<n>` | `50` | Maximum number of log entries. Minimum 1, maximum 100 |
| `-f, --follow` | `false` | Poll for new entries every 2 seconds until interrupted with Ctrl-C |
| `--cursor=<value>` | none | Continue from the cursor printed by the previous page |
| `--request-id=<value>` | none | Runtime logs only. Everything logged while serving one request |
| `--handler=<value>` | none | Runtime logs only. Lines from one Functions handler |

`--follow` polls, it does not stream over a socket. It dedupes by the whole entry and remembers up to 5,000 keys.

```bash
sf logs
sf logs runtime --follow
sf logs docs runtime
sf logs runtime --request-id req_9f21
sf logs runtime --follow --json
```

### Output

Access entries carry `timestamp`, `host`, `method`, `path`, `status`, and `bytes`. Runtime entries carry `id`, `timestamp`, `level` (`debug`, `info`, `warn`, or `error`), `requestId`, `versionId`, `handlerName`, `message`, and `metadata`.

Paged human output ends with `More: --cursor <value>` when there is another page, otherwise "Nothing logged yet." or "No requests yet."

`--follow --json` emits one JSON object per line, then a final `{"data":{"followed":true,"kind":"..."}}` when you interrupt it. That makes it safe to pipe into `jq`.

Log history is a plan limit. A request that reaches past your retention window is clamped to the effective start, with a `log_retention_clamped` warning naming it. See [limits](/limits).

### Errors

| Code | Exit | When |
| --- | --- | --- |
| `validation_error` | 2 | `kind` is not `access` or `runtime` |
| `validation_error` | 2 | `--request-id` or `--handler` passed with the access log |
