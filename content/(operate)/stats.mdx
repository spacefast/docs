Views exclude crawlers and failed requests. Requests count every HTTP request, and unique visitors use a separate daily count without those filters.

## Where to look

Open the Space and go to **Settings → Stats**. A segmented control labelled **Time period** switches between three windows.

| Window | Buckets |
| --- | --- |
| 48 hours | Hourly |
| 7 days | Daily |
| 30 days | Daily |

Thirty days is the longest window.

The page shows **Requests**, **Visitor requests**, and **Visitors per day**. Visitor requests include assets, not only page loads. Visitors per day averages complete UTC days in the selected window.

| Section | What it lists |
| --- | --- |
| Traffic by period | One row per bucket, with requests, visitor requests, visitors on daily windows, and bandwidth |
| Visitors | Daily distinct counts in the period table. The hourly window lists daily counts under the visitor card |
| Top paths | The busiest paths in the window |

Buckets are labelled in UTC. Bandwidth is available in the table's field picker but hidden by default. Cached and uncached traffic have [plan allowances and usage rates](/pricing).

## What counts as a view

A **request** is any HTTP request the Space answered. A **view** is a request with a status under 400 that didn't come from a crawler, assets included. `views` can't exceed `requests`; the difference is crawler traffic and responses with a status of 400 or higher.

**Unique visitors** come from a separate daily measurement. It ignores the crawler and status filters, and it counts every hostname mapped to the Space together. Visitors are only counted per day. Daily counts aren't added into a window total, so the dashboard shows daily counts and an average over complete days instead.

**Top paths** and top hosts are capped at 10 entries each.

## Where the numbers come from

The edge that serves your Space counts the requests. Nothing is added to your pages, no script runs in the visitor's browser, and no cookie is set. A static HTML file with no JavaScript is counted like any other file.

Each time you open stats, Spacefast reads them from the edge. It doesn't store its own copy. As a result:

- A Space that has never published a version has no runtime to read, and the request answers `runtime_not_provisioned`. Publish first.
- When stats can't be read, the page says **Analytics are temporarily unavailable** and offers **Try again** instead of showing zeros. Your Space keeps serving.

## From the CLI

```bash
sf analytics --space docs --window 30d
```

`--window` takes `48h`, `7d`, or `30d` and defaults to `7d`. The output prints the window, the granularity, the totals, then the per-day visitors, the top paths, and the series. Full flags and the `--json` shape are on [`sf analytics`](/cli/zero#sf-analytics).

## From the API

```bash
curl "https://api.spacefast.com/v1/spaces/spc_xxxxxxxx/analytics?window=7d" \
  -H "Authorization: Bearer sfa_xxxxxxxx"
```

[`getSpaceAnalytics`](/api/reference/activity/getspaceanalytics) returns one object.

| Field | What it holds |
| --- | --- |
| `window`, `since`, `until` | The window you asked for and the range it resolved to |
| `granularity` | `hourly` for `48h`, `daily` otherwise |
| `views` | Total views in the window |
| `bandwidthBytes` | Total bytes served |
| `series[]` | Per bucket: `bucket`, `requests`, `views`, `bandwidthBytes` |
| `visitorsByDay[]` | Per day: `date`, `visitors` |
| `topPaths[]` | `path` and `views`, up to 10 |
| `topHosts[]` | `host` and `views`, up to 10 |

There is no window-level request total in the payload. Sum `series[].requests` for it, which is what the dashboard does.

## Add browser analytics

For browser analytics, add your own tag. **Customization → Google Analytics** takes a GA4 measurement ID or a Tag Manager container ID, each with a switch that controls whether the tag loads. See [Customization](/customization).
