After this page you can set a variable without putting it in your shell history, import a whole `.env` file, pull the readable ones back into a local file, and know exactly when a change takes effect.

Every command here takes the global flags (`--api-url`, `--profile`, `--token`, `-y`/`--yes`, `--json`). All except `sf env export-template` also take the space selection flags (`--space`, `-o`/`--team`, `--claim-token`). See [the CLI overview](/cli).

## How variables behave

A write is applied **when a version next finalizes**. The live version keeps the values it was sealed with, so setting a variable does not change what is serving until you publish again or the debounced re-finalize lands.

Names are 1 to 128 characters matching `^[A-Za-z_][A-Za-z0-9_]*$`. Names starting with `SPACEFAST_` are reserved and rejected.

A variable is either ordinary or write-only. A write-only value is never returned by the API, the CLI, the dashboard, diagnostics, logs, or activity. New values default to write-only; updates keep whatever classification the variable already had. Versions record variable names and SHA-256 hashes of the values, never the values.

## sf env ls

List space variables. Aliased as `sf env list`.

```text
sf env ls [--space <value>] [--show-values]
```

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--show-values` | `false` | Print plaintext variable values |

```bash
sf env ls --space docs
```

### Output

A table of variables with values masked as `********`. The mask applies on the `--json` path too, so `--json` without `--show-values` gives you names and classifications, not secrets.

With `--json`, `data` is `{ variables, systemVariables }`. `systemVariables` holds the read-only `SPACEFAST_*` values the platform provides.

## sf env set

Create or update a space variable. Values are sent to the API and are not printed back.

```text
sf env set <name> [value] [--space <value>] [--value-from-stdin] [--secret]
  [--production-value <value>] [--preview-value <value>] [--branch-value <branch=value>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `<name>` | Variable name. Required |
| `[value]` | Variable value. Omit it and pass `--value-from-stdin` for secrets |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--value-from-stdin` | `false` | Read the value from standard input, keeping it out of your shell history and process list |
| `--secret` / `--no-secret` | write-only for new values | Keep the value write-only. Updates preserve the existing classification unless you pass this |
| `--production-value=<value>` | none | Value to inject for production builds |
| `--preview-value=<value>` | none | Value to inject for preview builds |
| `--branch-value=<branch=value>` | none | Value to inject for a branch build. Repeatable |

Passing both a positional `value` and `--value-from-stdin`, or neither, is a validation error. Stdin strips exactly one trailing newline; empty stdin is an error. A write-only value passed on argv gets a warning naming the variable, never the value.

`--branch-value` must be `branch=value`. An empty branch or an empty value is a validation error.

```bash
printf %s "$API_TOKEN" | sf env set API_TOKEN --value-from-stdin --space docs
sf env set PUBLIC_ORIGIN https://www.example.com --no-secret --space docs
```

## sf env rm

Delete a space variable. Aliased as `sf env remove` and `sf env delete`.

```text
sf env rm <name> [--space <value>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `<name>` | Variable name. Required |

No command-specific flags.

This is a destructive remote action. It prompts, naming the variable and the Space, unless you pass `-y`.

```bash
sf env rm API_URL --space docs
```

## sf env import

Import variables from a dotenv file. Values are sent to the API and are not printed back.

```text
sf env import <file> [--space <value>] [--secret] [--production] [--preview]
  [--branch <name>] [--from dotenv|vercel|netlify|cloudflare]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `<file>` | `.env` file to import. Required |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--secret` / `--no-secret` | write-only for new values | Keep imported values write-only. Updates preserve existing classifications |
| `--production` | `false` | Also store each imported value for production builds |
| `--preview` | `false` | Also store each imported value for preview builds |
| `--branch=<name>` | none | Also store each imported value for an exact branch. Repeatable |
| `--from=<dotenv\|vercel\|netlify\|cloudflare>` | `dotenv` | Platform export format to import. Vercel, Netlify, and Cloudflare all use dotenv exports |

The parser strips a BOM, skips blank and `#` lines, strips a leading `export `, and unescapes `\n`, `\r`, `\t`, `\"`, `\\`, and `\$` inside double quotes. An inline `#` outside quotes is stripped. A missing `=` is an error naming the line, an unclosed quote is an error, and **an empty value is an error**. A later duplicate overwrites an earlier one. Imports are one write per entry, in file order.

```bash
sf env import .env --space docs
sf env import public.env --space docs --no-secret
```

## sf env pull

Pull effective space and shared variables into a local env file.

```text
sf env pull [file] [--space <value>] [--format env|json] [--force] [--stdout]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `[file]` | File to write. Defaults to `.env.local` |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--format=<env\|json>` | `env` | Output format |
| `--force` | `false` | Overwrite the target file if it already exists |
| `--stdout` | `false` | Print variables to stdout instead of writing a file |

Only non-secret variables with a string value are pullable. Write-only names are reported as omitted with a warning instead of being written. Shared (principal-scope) entries are written as `shared.<NAME>`.

The overwrite guard uses `lstat`, so a dangling symlink also trips it. The file is written with mode `0600` through a temp file and rename.

```bash
sf env pull --space docs
sf env pull .env.development --space docs --force
sf env pull --space docs --stdout --format json
```

## sf env export-template

Read platform config files and print a dotenv template for variables to import into Spacefast. This runs entirely on your machine. No space flags, no API call.

```text
sf env export-template [dir] [--format env|json]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `[dir]` | Project directory to inspect. Defaults to the current directory |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--format=<env\|json>` | `env` | Output format |

It reads `package.json`, `vercel.json`, `netlify.toml`, and `wrangler.toml`/`.json`/`.jsonc` from the directory and nothing else.

```bash
sf env export-template
sf env export-template ./app --format json
```
