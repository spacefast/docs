Every Space starts with your files and grows into a full-stack app in one project. Start with HTML, a frontend framework, or `sf init` (which scaffolds a SpacePress app by default), then turn on database, Workers, email, storage, crons, and connectors as you need them.

## SpacePress is built into every Space

SpacePress is Spacefast's full-stack TypeScript layer. Write your schema, queries, actions, jobs, and TSX pages in TypeScript under `sp/`. On publish, Spacefast compiles them to native WordPress and PHP with no Node.js server to manage.

Configure your Space in `spacefast.config.ts` with `defineConfig` from `spacefast/config`. You can declare app settings inline under `app` in `spacefast.config.ts` or in a standalone `spacepress.config.ts` beside it, but not both in the same project. `sf.jsonc` remains permanently supported as the JSON fallback; see [Configuration](/config-file).

```ts spacefast.config.ts
import { defineConfig } from "spacefast/config";

export default defineConfig({
  name: "my-space",
  app: {
    collections: {
      posts: { title: "Posts" },
    },
    actions: {
      subscribe: { access: "anyone" },
    },
  },
  crons: [{ path: "/api/digest", schedule: "daily" }],
  connectors: {
    crm: { connector: "hubspot", tools: ["list_deals"], cache: "60s" },
  },
  templates: ["index.html"],
});
```

Every capability publishes and rolls back with your Space's versions. Preview channels run against an isolated SQLite database per version so preview edits never touch live MySQL data.

## Capabilities

| Capability | What it does |
| --- | --- |
| [Collections and CMS](/collections) | SpacePress storage kinds (`collection()`, `table()`, `global()`, `taxonomy()`, `wp.posts.extend()`), typed fields, TSX pages, `"use client"` islands, Markdown sync, and WooCommerce stores |
| [Actions, queries, and jobs](/actions) | Typed `query()` and `mutation()` server functions, zero-JS forms, transactional hooks, Action Scheduler background `job()`s, custom HTTP routes, and human approval continuation |
| [Database and ORM](/database) | Dedicated MySQL per Space, visitor-scoped `spacepress/server/db` queries, Drizzle-inspired `db` ORM, declarative access rules, forward-only SQL migrations, `env.DB`, `sf db`, and a single-use SQL console |
| [WordPress and Content API](/wordpress) | SpacePress Admin (`/wp-admin/new/`), one-use admin links, proxied and direct WordPress REST APIs, WordPress Abilities, three-way content sync, generated typed clients, `sf app wp`, and `sf apply` |
| [Workers](/functions) | Server-side JavaScript and TypeScript via `functions/`, a root `handler.ts`, `"use worker";` SpacePress routes, or OpenNext, with `env.SPACE`, `env.DB`, `env.STORAGE`, and `env.CONNECTORS` bindings |
| [Transactional email](/email) | Outbound mail signed with your primary custom domain, React Email templates (`emails/*.tsx`), `mail.render()`, and transactional `mail.send()` |
| [Object storage](/object-storage) | Runtime file uploads separate from published version files, with private and public access plus SpacePress `files()` buckets |
| [Crons](/crons) | Scheduled `GET` requests declared in `spacefast.config.ts`, alongside recurring SpacePress jobs and `cron()` handlers |
| [Environment variables](/environment-variables) | Space- and team-scoped variables, write-only secrets, and build-time template substitution |
| [Connectors](/connectors) | Connect external REST APIs, GraphQL endpoints, and MCP servers with credentials sealed on the server |

## Local workflow and scaffolding

Scaffold a SpacePress app, add owned starter recipes, validate offline, and publish:

```bash
sf init my-space
sf add form
sf check
sf dev
sf publish
```

- [`sf init`](/cli/reference#sf-init-name) scaffolds a SpacePress `app` project by default (`spacefast.config.ts`, a `notes` collection, `sp/actions.ts`, and `sp/app/page.tsx`), or pass `--template static`, `next`, or `astro`. See [Starters and templates](/guides/starters).
- [`sf add`](/cli/reference#sf-add-recipe-directory) writes plain source files you own and edit directly: `form` (contact table, mutation, and form), `shop` (native WooCommerce store, checkout block, and synced products), `auth` (Sign in with Spacefast and `/account`), or `ai-route` (streaming `functions/api/chat.ts` route).
- [`sf check`](/cli/reference#sf-check-dir) validates `spacefast.config.ts` (or `sf.jsonc`), SpacePress schemas and handlers, routing rules, Worker routes, and scans publishable files for secrets in one offline pass.
- [`sf dev`](/cli/reference#sf-dev) starts your framework dev server and runs `functions/` Workers locally. For a full local WordPress + SQLite server with live rebuilds on `sp/` edits, run `npx spacepress dev` or publish to a Spacefast preview channel.
- Moving an older Zero 0.8 or `zero.config.ts` Space? See [Migrating from Zero 0.8](/zero-migration).
