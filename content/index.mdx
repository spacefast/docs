Spacefast publishes what people build with AI agents. You hand it a folder, it hands back a URL. Publish from the dashboard, the `sf` CLI, the HTTP API, or an MCP server. An agent with publishing permission can ship what it built.

If you prefer a browser, drag a folder onto [drop.fast](https://drop.fast) (no install, no account required; see [Drop](/publish#publish)). If you already have a website, paste its address into the [website importer](https://spacefast.com/migrate/) to copy it into a Space (see [Copy a website](/migrate)).

## Publish in one command

```bash
npm install -g spacefast
```

```bash
sf publish ./dist
```

No account needed for the first publish. The CLI creates a Space, uploads the files, and prints a live URL plus a claim link. Sign in later to keep it.

```text
Published: https://quiet-harbor.space.fast

  Open          https://quiet-harbor.space.fast
  Version URL   https://quiet-harbor--v1.space.fast
  Version       v1 (ready)
  Files         12
  Duration      3.2s
```

Or ask the agent that built it.

## How it fits together

A **Space** holds your published files. Each publish that changes something creates a **version**, an immutable snapshot with its own URL. The `live` channel points at the version visitors see, and is empty before the first publish. Promoting or rolling back moves that pointer to another retained, ready version without rebuilding. Preview publishes and manual promotion policies leave `live` where it is. For other terms, see the [glossary](/glossary).

Most Spaces are static. Point `sf publish` at a build directory and it uploads only the files that changed. To publish source instead, let Spacefast detect the framework and build it. Spaces that need server code run on [Functions](/functions), which runs a worker with npm packages, or [Zero](/zero-runtime), which adds live queries and a schema Spacefast migrates. Both get a database, and [crons](/crons) can call either.

In a self-serve account, your team owns the Spaces you claim, even when you are its only member. On [Pro](/pricing), you can add members who publish and roll back without sharing your login. Personal and Go allow only the owner. Team roles control who can manage domains, credentials, and billing. See [Teams and members](/teams) to invite people and choose how new Spaces are shared.
