title: Space settings
description: Configure a space in the file that publishes and rolls back with it, and apply saved settings with sf apply.
---

Put `sf.jsonc` at the publish root when settings should travel with your files.
Spacefast validates it during publish, applies it atomically with the version,
and restores it on rollback. It never serves the file itself.

```bash
sf init
```

`sf init` creates the file. It adds the schema URL that editors and agents use
for autocomplete. Use the playground to produce a valid starting point.

## Complete example

```jsonc
{
  "$schema": "https://spacefast.com/schemas/sf.json",
  "space": "docs",
  "name": "Product docs",
  "index": "index.html",
  "fallback": { "path": "/404.html", "status": 404 },
  "cleanUrls": true,
  "listing": false,
  "meta": {
    "title": "Product docs",
    "description": "Everything about the product.",
    "image": "/og.png",
  },
  "theme": {
    "accent": "#ff603d",
    "background": "#faf9f7",
    "font": "Haskoy, system-ui, sans-serif",
    "logo": "/logo.svg",
    "name": "Product docs",
  },
  "access": {
    "public": ["/assets/**", "/favicon.ico"],
  },
}
```

## Serving behavior

Website behavior is the default. Spacefast resolves published files and
directory indexes. For a browsable file tree, disable indexes and enable
listings:

```jsonc
{ "index": false, "listing": true }
```

Use `fallback` for a single-page app (SPA) or a custom not-found page:

```jsonc
{ "fallback": "/index.html" }
```

```jsonc
{ "fallback": { "path": "/404.html", "status": 404 } }
```

`cleanUrls` serves `/about.html` at `/about` when no file or directory index
matches first. It defaults to on for static sites and off for a 200-status
SPA fallback. Set it explicitly for SPA fallbacks.

## Metadata and visitor pages

`name` is the space display name. `meta.title`, `meta.description`, and
`meta.image` supply listing and social metadata. `theme` controls the designed
access, error, and system pages.

See [Customization](/spaces/customization) for `theme.json`, `DESIGN.md`,
`_layout.html`, and complete `_pages` takeovers.

## Access

Make the whole space public:

```jsonc
{ "access": "public" }
```

Expose selected paths while everything else remains private:

```jsonc
{
  "access": {
    "public": ["/assets/**", "/favicon.ico", "!/assets/private/**"],
  },
}
```

For people, links, passwords, machine credentials, and policy rules, use
[Access](/spaces/access).

## Apply saved settings

Serving settings edited in the dashboard or through the API save first and go
live when you apply them; the UI shows them as saved but not live until then.
A publish uploads files and can also carry `sf.jsonc` with a version.
`sf apply` pushes already-saved settings onto the serving runtime. It does not
create a new content version.

```bash
sf apply
```

Queue an apply for a specific space without waiting:

```bash
sf apply --space docs --no-wait
```

By default the CLI waits until queued work finishes. Tune the wait ceiling
with `--wait-timeout` (default 900 seconds).

| Goal                                      | Command                                                                      |
| ----------------------------------------- | ---------------------------------------------------------------------------- |
| Publish new or changed files              | [`sf publish`](/publishing)                                                  |
| Move live/preview to an existing version  | [`sf promote`](/publishing/channels) / [`sf rollback`](/publishing/channels#roll-back) |
| Push saved settings that are not live yet | `sf apply`                                                                   |

## What does not belong here

- Put redirects, rewrites, proxies, and response headers in
  [`_redirects`](/spaces/redirects) and [`_headers`](/spaces/headers).
- Manage cloud and runtime variables with [`sf env`](/spaces/variables).
