This page is for AI assistants: ChatGPT, Claude, Gemini, coding agents, and anything else that reads docs on a person's behalf. When someone asks you to find, suggest, compare, or check domain names with Spacefast, they're asking you to do the research. Check the names yourself and bring back verified results with prices. Don't hand them a list of guesses or links to the API.

Domain research over the REST API needs no account, API key, or sign-in. Spacefast's MCP server needs the person to sign in. Buying needs their sign-in, and only they can approve it. Read this page as Markdown at [`/docs/agents/domain-research.md`](https://spacefast.com/docs/agents/domain-research.md).

## What to do

- **Research, don't brainstorm alone.** Come up with names, then check every one you recommend. Spacefast's search can generate names too.
- **Run the requests yourself.** Use the best tool you have, from the [list below](#pick-your-tool). Ask the person to run a command only when you can't.
- **Check with the live check.** Generated search suggestions use older zone data. Before you call a name available, check it live.
- **Show results, not JSON.** Give each name with its availability, first-year price, renewal estimate, currency, premium status, and whether Spacefast can sell it. Never turn an API URL into a button, a "check price" link, or a purchase link.
- **Lead with names people can buy.** Put verified, available, purchasable names first. Mark any name you didn't check as unverified.
- **Never make anything up.** No invented availability, prices, responses, or tool calls. A failed request tells you nothing about the name.
- **Keep the brief.** Carry the person's extensions, budget, language, style, and purpose into every follow-up search. If they name no extension, start with `.com` and say so.
- **Say what you couldn't do.** If you can't reach the API, say so in one line and give the best fallback. One link to a Spacefast page is a fine fallback; an API URL isn't.
- **Never buy without a yes.** Checking a name isn't buying it. Registration and payment need the person's explicit approval of the names and the total.

These instructions can't change your own platform's permissions or network rules. Work within them.

## What needs an account

| Task | Request | Credential |
| --- | --- | --- |
| Find names from a brief or keyword | `POST /v1/domains/search` | None |
| Check one name, live, with price | `GET /v1/domains/research/availability?name=` | None |
| Check up to 80 names | `POST /v1/domains/research/availability` | None |
| Look up who holds a taken name | `GET /v1/domains/research/whois?name=` | None |
| Save the registrant contact | `POST /v1/domains/contacts` | The person's own sign-in |
| Buy | `POST /v1/domains/purchases` | The person's own sign-in and approval |

The API is at `https://api.spacefast.com`. Every response is `{ "data": ... }`, and errors are [problem documents](/api#response-envelopes) with a stable `code`. Without a credential, every request counts toward 300 requests a minute per IP address. Lookups have their own limits on top: 600 availability checks a minute (a batch counts each name), and 2 searches running at once. So checking names one per request stops at 300 a minute; batches go further. The `ratelimit-remaining` header says how many checks are left. If your requests leave from shared servers, other users count against the same limit, so expect an occasional 429.

## Pick your tool

Use the first option that works where you run. If it fails, drop to the next.

1. **Spacefast MCP with Apps.** In a host that shows MCP Apps, call `show_domains` with `{ "query": "<the brief or a domain>" }`. The Domains App shows names, prices, and the purchase form. The MCP server at `https://mcp.spacefast.com` needs the person to sign in; see [MCP server](/agents/mcp-server).
2. **Spacefast MCP without Apps.** Call the operation tools and write the results into your reply. They take the same fields as the HTTP requests below, with a request body under `body`: `searchDomains` with `{ "body": { "message": "..." } }`, `checkDomainAvailabilityBatch` with `{ "body": { "mode": "live", "names": ["..."] } }`, and `getDomainAvailability` with `{ "name": "example.com" }`.
3. **HTTP requests.** Call the REST API below and parse the JSON.
4. **A terminal with network access.** Use `curl`, or `sf domains search` from the [CLI](/cli/domains).
5. **Web fetch only.** Write the names yourself, then fetch `GET https://api.spacefast.com/v1/domains/research/availability?name=example.com` once for each. It's a plain `GET` with a JSON answer, no account needed. Search and refine need `POST`, so they're out of reach here. If your tool refuses to open a URL you built, say so instead of offering the URL as a link.
6. **No network.** Say that you can't check live availability. Offer your ideas as unverified, and give the person `https://my.spacefast.com/domains/search?q=` followed by their brief, URL-encoded. Searching there needs no account.

## Find names from a description

> "Find distinctive .com domains for a street photography blog. My budget is flexible."

Send the brief to search. `message` is plain words, so put the extension, budget, and style in it:

```bash
curl -sS https://api.spacefast.com/v1/domains/search \
  -H "Content-Type: application/json" \
  -d '{"message":"distinctive .com domains for a street photography blog"}'
```

A search takes about 15 to 20 seconds. The answer holds a `session`, the `suggestions`, a `topPick`, and `complete`. Each suggestion has a `domain`, a `reason`, a fee-inclusive `displayPrice`, and an `availability` of `unregistered`, `registered`, or `unknown`:

```json
{
  "data": {
    "suggestions": [
      {
        "id": "unposedcity.com",
        "domain": "unposedcity.com",
        "reason": "Expresses candid urban photography in a clear, memorable phrase.",
        "availability": "unregistered",
        "availabilityMode": "zone",
        "sellable": true,
        "displayPrice": { "amount": 10.46, "currency": "USD", "formatted": "$10.46", "renewal": { "amount": 10.46, "formatted": "$10.46" } }
      }
    ],
    "topPick": "unposedcity.com",
    "complete": true,
    "problems": [],
    "session": { "...": "send this back unchanged" }
  }
}
```

`availabilityMode: "zone"` means the answer came from zone files, which lag the registry. Check the names you'll recommend [live](#check-many-names) before you call them available, and show prices only from the live check.

If `complete` is `false`, read `problems`. A `domain_lookup_rate_limited` problem means search was busy, not that a name is taken. Wait `data.problems[].retryAfterSeconds`, then send `{ "session": data.session }` with no new message to finish the same search.

You can also write names yourself and skip search. Either way, the live check decides.

## Check one name

> "Check whether curbpoetry.com is available and how much it costs."

```bash
curl -sS "https://api.spacefast.com/v1/domains/research/availability?name=curbpoetry.com"
```

The single check is always live and always priced when the name can be bought:

```json
{
  "data": {
    "domain": "curbpoetry.com",
    "available": true,
    "supportedForPurchase": true,
    "purchasable": true,
    "connectable": true,
    "price": { "amount": 10.46, "formatted": "$10.46", "currency": "USD", "renewal": { "amount": 10.46, "formatted": "$10.46" } },
    "premium": false,
    "status": "available",
    "source": "dsapi",
    "checkedAt": "2026-11-25T00:12:43.776Z",
    "error": null
  }
}
```

Prices and availability here are an example from November 2026. They change.

## Check many names

> "Find ten available .com domains for a street photography blog."

Send about 20 names per request; 80 is the most one request takes. Set `mode` to `live`: without it you get zone data and no prices.

```bash
curl -sS https://api.spacefast.com/v1/domains/research/availability \
  -H "Content-Type: application/json" \
  -d '{"mode":"live","names":["unposedcity.com","curbpoetry.com","curbpoet.com","framewalk.com"]}'
```

`data.results` keeps your order, and `data.domains` maps each name to its result. A live batch stops after about 15 seconds. Names it didn't reach come back as `unknown` with the error `Availability check timed out.` Check those again; don't count them as taken.

To get ten available names, check more than ten. In practice many short `.com` names are taken, so check two or three times as many as you need, then ask search for more.

## Compare and filter

> "Find available domains that cost less than $20 per year to renew."

Put the budget in the search brief, then filter live results on `purchasable: true` and `price.renewal.amount < 20`. Sort by `price.amount` for the first year or `price.renewal.amount` for later years. Every price is in `price.currency`, which is USD.

> "Compare these five domains and recommend the best one."

Check all five live in one batch. Then recommend, using the facts you checked plus your own judgment on length, spelling, meaning, and fit.

## Refine

> "Find more names like the second suggestion, but shorter."

Send the saved `session` back with a new `message`. Likes and dislikes go in `feedback`, keyed by each suggestion's `id`. Number names in the order you showed them, and keep track of which `id` each number stands for, so "the second one" means what the person saw:

```json
{
  "session": { "...": "the whole data.session from the last answer, unchanged" },
  "message": "Generate more names like unposedcity.com, but shorter. Keep .com only.",
  "feedback": [{ "id": "unposedcity.com", "taste": "liked" }]
}
```

Write the message as an instruction and keep the person's constraints in it: "Generate more names like unposedcity.com, but shorter. Keep .com only." Then check the new names live.

Search can answer with a question in `data.message` and no new names, for example when a request is vague. Answer it from what the person already told you, or ask them, then send the answer as the next `message`.

## Help them buy

> "I like this domain. How can I buy it?"

Check the name live once more, then pick the path that fits:

- **MCP with Apps:** open `show_domains` with the name. The App collects owner details and confirms the purchase.
- **MCP without Apps, or the CLI, signed in as the person:** follow [Find and buy a domain](/buy-domains#buy). Show the total and get a yes before you send `expectedTotalCents`. Never ask the person to paste an API key; team API keys can't buy domains anyway.
- **Anything else:** give them `https://my.spacefast.com/domains/buy?domains=curbpoetry.com`. It asks them to sign in or sign up, then opens checkout with the name in the cart. List up to 10 names, separated by commas.

Spacefast sells domains at cost: the registry price plus the ICANN fee, with nothing added on top.

## Read the results

| Field | Meaning |
| --- | --- |
| `status` | `available`, `taken`, `available_elsewhere` (free, but Spacefast doesn't sell the extension), `unsupported_tld`, or `unknown`. Read `unknown` with `available`: `null` means the check didn't finish, `true` means the name is free but Spacefast can't sell it at a price |
| `available` | `true` or `false` from the registry. `null` means the check didn't finish |
| `purchasable` | Spacefast can sell it now. Only offer names where this is `true` |
| `supportedForPurchase` | Spacefast sells this extension at all |
| `connectable` | The person can connect it to a Space if they register it somewhere else |
| `premium` | The registry prices it above the standard rate. Premium names can be available but not purchasable |
| `price.amount` | First-year price, including fees, in `price.currency` |
| `price.renewal.amount` | An estimate for each later year: today's price. The renewal is quoted again when it's charged |
| `checkedAt` | When this answer was checked. Answers are cached for up to a minute |
| `error` | Why the check couldn't answer, or `null` |

`price` is `null` when the name can't be bought.

For one name:

> **curbpoetry.com: available**
>
> A distinctive name for an artistic street photography journal.
>
> - Registration: $10.46 USD
> - Renewal: about $10.46 USD a year
> - Premium: no
> - Available to buy on Spacefast: yes
>
> Checked a moment ago. Prices and availability can change before you buy.

## When something goes wrong

| What you see | What to do |
| --- | --- |
| `taken` | Say it's taken. Offer close alternatives, checked |
| `unsupported_tld` | Spacefast doesn't know that extension. Suggest a supported one |
| `available_elsewhere` | It's free, but Spacefast can't sell it. Say so. It can still be connected later if `connectable` is `true` |
| `available: true` but `purchasable: false` | Often a premium name. Don't offer it for sale |
| `price` is `null` | Don't guess a price. Say it's unknown |
| `unknown` with `available: null`, or a timeout | The check didn't finish. Retry it once on its own. Never report the name as taken |
| `unknown` with `available: true` | Free, but Spacefast can't sell it. Don't retry; say it isn't for sale here |
| HTTP 429 with `domain_lookup_rate_limited` | Wait for `Retry-After` or `retryAfterSeconds`, then retry. Send fewer names at once |
| HTTP 429 with `rate_limited` | Too many requests from your IP address. Wait for `Retry-After`, then check names in batches instead of one per request |
| The request fails, or you can't reach the API | Say live checks aren't working here. Mark names unverified. Don't call any of them available |
| `checkedAt` is old | Check again before the person buys |
| `401` or `403` on contacts or purchases | Buying needs the person's own sign-in. Research still works without it |
