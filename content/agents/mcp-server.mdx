The hosted MCP server uses OAuth and accepts inline files. The local server uses your CLI login or `SPACEFAST_TOKEN` and can publish files from your workspace.

You don't need this page. It's the technical reference for wiring up the MCP server by hand — see [Claude Desktop](/agents/claude-desktop) or [Claude Code](/agents/claude-code) for the point-and-click setup instead.

## Two runtimes, one tool catalog

The same server ships in two runtimes. Both expose each eligible Spacefast API operation as its own tool. The difference is the filesystem.

| | Hosted | Local |
|---|---|---|
| Transport | Streamable HTTP | stdio |
| Endpoint or command | `https://mcp.spacefast.com` | `sf mcp`, or `npx -y spacefast mcp` |
| Filesystem | None. `publish` takes inline `files` or a completed `uploadId` | Reads your workspace. `publish` also takes a `path` or publishes the current workspace |
| Auth | OAuth, per client | Your CLI login, or `SPACEFAST_TOKEN` |
| Where it runs | Spacefast | Your machine |

The hosted endpoint also answers on `/mcp` and `/mcp/`. Only the `mcp.` hostname serves MCP; the path `/mcp` on the API host does not.

There is a third lane, `sf mcp proxy`, which speaks stdio to your editor and HTTPS to the hosted endpoint using your CLI login. It is what `sf setup agent` writes by default. See [other clients](/agents/other-clients).

## Authentication

### Hosted

The hosted server is an OAuth 2.0 protected resource. It is never anonymous. A request with no token gets a `401` and a `WWW-Authenticate` challenge pointing at the resource metadata document. Your client walks the rest from there. Bearer and DPoP are both accepted; a DPoP-shaped request gets a DPoP challenge back.

The resource identifier is the MCP origin itself. A platform OAuth token not bound to the MCP resource is rejected here, even though it's a valid Spacefast token.

By default a client asks for these scopes.

| Scope | What it grants |
|---|---|
| `teams:read` | Read the teams the account belongs to |
| `teams:create` | Create teams |
| `teams:members.write` | Invite people to teams the account can administer |
| `sell:write` | Set up Sell, enable live sales, resend downloads, and mark orders shipped |
| `spaces:read` | Read spaces, versions, and build status |
| `spaces:write` | Create and update spaces and their settings |
| `spaces:rename` | Rename space slugs and managed addresses |
| `spaces:access.write` | Change who can open a site, including making it public |
| `versions:download` | Read files from deployment versions |
| `publish:write` | Publish new immutable versions |
| `domains:read` | Read Space hostnames and certificate status, plus registrations and DNS records when enabled |
| `domains:write` | Manage Space hostnames, plus buying domains and managing DNS records when enabled |
| `offline_access` | Refresh access without another sign-in |

`spaces:delete` is the one scope left out of the default. Add it to the request, or approve it when an agent asks to delete a Space.

Each tool declares the scopes it needs in `tools/list`, under `_meta["spacefast/requiredScopes"]`. An operation tool takes its scopes from the API operation it calls, and the API checks them again on every call. When a call needs a scope your grant lacks, a client that supports MCP step-up authorization asks you to approve it and retries.

The hosted server mints a delegation token for each authenticated request instead of handing your client a Spacefast API token. That delegation token lives five minutes and carries the source credential's policy verbatim, so a leaked MCP session can't be replayed against the wider API.

Hosted requests are rate limited to 600 per minute per credential and 300 per minute per IP.

### Local

The local server takes its credential from the process, never from client config. `sf mcp` resolves your CLI login and hands it to the in-process server. Standalone runs read `SPACEFAST_TOKEN`.

| Variable | Effect |
|---|---|
| `SPACEFAST_TOKEN` | Bearer token for API calls |
| `SPACEFAST_API_URL` | API base URL |
| `SPACEFAST_MCP_WORKSPACE_ROOT` | Pins the one directory `publish` may read from |

## The tools

### Operation tools

Each API operation exposed through MCP is a tool named by its `operationId`: `getAccount`, `listSpaces`, `searchDocs`, `createDomain`, `promoteSpaceVersion`, and a few hundred more. Its input schema is the operation's own contract, with `path`, `query`, and `body` groups. Its result is the API response. There is nothing to discover at runtime and no program to write: read the schema from `tools/list`, then call the tool.

That is a big list. Clients that support tool search load the tools they need on demand. A client that loads everything up front still works, just with a larger tool list.

A few operations stay in the dashboard, such as buying a domain. The `domains:write` scope does not add a domain-purchase MCP tool. A few stay in the CLI and API, such as claiming an anonymous Space with its key. Those have no tool.

### Product tools

A handful of tools sit on top of the catalog.

| Tool | What it does | Key inputs |
|---|---|---|
| `publish` | Uploads files and creates an immutable version | `path`, `files`, or `uploadId`, plus `spaceId`, `teamId`, `access` |
| `operation_status` | Checks a publish that is still running | `url` or `operationId` from the publish result |
| `show_space_*` | Opens a visual view of one Space | `space`, plus the view's own fields |
| `show_domains` | Searches domain names and compares prices | `team`, `query` |
| `choose_space` | Asks you to pick a Space when the target is unclear | `query` |
| `resume_execution` | Continues a call that paused for approval | `executionId` |
| `cli_login` | Signs the `sf` CLI in with this connection's access, when you ask for it | None |

The local runtime adds `search_connector_tools`, which reaches services your team connected in Spacefast. The hosted runtime adds `import-claude-design-from-url` and `get-design-import-job-status` for Claude Design.

Every result is capped at 24,000 characters of text across the whole structured value, with an explicit truncation marker when it hits the cap. Source views have their own byte limits.

### publish

`publish` is synchronous by default. It waits for the version to finalize and returns the receipt.

| Field | Type | What it does |
|---|---|---|
| `path` | string | Local runtime only. One local directory, file, or archive. Omit `path`, `files`, and `uploadId` to publish the current workspace |
| `files` | array of 1 to 1000 | Inline files. Each is `{ path, content, encoding }` with `encoding` one of `utf8` or `base64`, default `utf8` |
| `uploadId` | string | A completed durable upload from `completeUpload`, for files too big to send inline. Reuse it when retrying |
| `spaceId` | string starting `spc_` | Update this Space. Omit to create one, or on local to use the Space linked to this workspace |
| `teamId` | string | Destination team id or slug for a new Space. Send one after a `team_required` error |
| `access` | `private` or `public` | Initial root access for a Space this publish creates. `private` admits the owning team, `public` also admits anyone on the web. Omit to use the team default. Invalid with `spaceId` |
| `createNew` | boolean, default `false` | Local runtime only. Forces a separate Space. Invalid with `spaceId` |
| `slug` | string, 2 to 55 | Slug for a new Space |
| `title` | string, 1 to 255 | Title for a new Space |
| `description` | string, up to 2000 | Changelog for this version. It does not change the Space description |
| `requestId` | string, 16 to 200 | Idempotency handle. Reuse the same value only when retrying a call that timed out |

Send at most one of `path`, `files`, and `uploadId`.

```json
{
  "path": "dist",
  "description": "Fix the pricing table"
}
```

The result carries `status` of `publishing` or `published`, `liveUrl`, `immutableUrl`, and a `receipt` with the Space, the version, and any diagnostics. When `status` is `publishing`, `result.job.poll` holds the handle for `operation_status`.

Archives are recognized by extension: `.zip`, `.tar`, `.tgz`, `.tar.gz`.

### operation_status

| Field | Type | What it does |
|---|---|---|
| `url` | string | Copy `publish.result.job.poll.url`. Prefer it when present |
| `operationId` | string | Copy `publish.result.job.poll.operationId` |

Send exactly one of the two.

```json
{ "operationId": "opr_7f2b8c1d4e5a6b7c" }
```

Poll about every two seconds. Stop when `result.done` is true. Report success only when `result.status` is `succeeded`; the other terminal states are `failed` and `canceled`.

### Space views

Each view is its own tool. Pass the Space as an id, slug, hostname, or URL. Detailed views require a claimed Space.

| Tool | What it shows |
|---|---|
| `show_space_preview` | One deployed version, for visual review |
| `show_space_deployments` | Deployment history and build status |
| `show_space_domains` | Domains, DNS records, and TLS status |
| `show_space_analytics` | Traffic over the selected window |
| `show_space_comments` | Comment threads with replies and screenshots |
| `show_space_source_files` | Repository files and folders |
| `show_space_source_changes` | Pending source workspace changes |
| `show_space_source_history` | Repository commits |
| `compare_space_source_versions` | Differences between source commits |
| `compare_space_deployment_versions` | Differences between published versions |
| `show_space_build_logs` | Logs from one build |
| `show_space_database` | The database schema, rows, and table relations |

```json
{ "space": "docs.example.com" }
```

A view never changes anything. Call the matching operation tool for changes.

### Find documentation

Call `searchDocs` with your query, then `getDocsPage` with a result's slug for the full page. `listDocs` lists every page.

For an error, open the problem document's `type` URL to read the matching error page.

## Approvals

A sensitive write can pause before its HTTP request goes out.

<Steps>
  <Step title="The call pauses">
    The tool returns `status: "user_approval_required"` with an `executionId`, and either an `approvalUrl` or an approval card in clients that render MCP Apps.
  </Step>
  <Step title="You decide">
    The card or the approvals page in the dashboard shows the exact action the agent wants to run. Approve or decline it.
  </Step>
  <Step title="The agent resumes">
    The agent calls `resume_execution` with the same `executionId`. If you have not decided yet, it gets `user_approval_required` again. Once you decide, the saved call runs exactly once.
  </Step>
</Steps>

A pause waits up to 24 hours for a decision, so you can step away. The agent must reuse the `executionId`; calling the original tool again starts a separate request instead of resuming this one.

On the local runtime there is no browser step. The agent relays your decision itself.

| Field | Type | What it does |
|---|---|---|
| `executionId` | string, required | The id from the paused result |
| `action` | `accept`, `decline`, or `cancel` | Your decision. Local runtime only |
| `content` | string, default `"{}"` | JSON-encoded form response. Leave the default when the pause has no form fields |

```json
{ "executionId": "exe_9c3f1b7a20d4" }
```

Choosing "always allow" is deliberately narrow. Only a plain confirmation gate, a pause with nothing to fill in, can be auto-approved later. A pause that asks you to open a URL, or one that wants form content, always comes back to you.

If the request changes between the pause and your decision, the resume fails and nothing runs. Make the call again.

Tools also declare how risky they are, and clients use that to decide what to confirm on their own. Read operations are marked read-only. Writes, `publish`, and `resume_execution` are marked destructive.

## Local file access

Only the local runtime reads files, and it reads them from exactly one directory.

The workspace root is resolved in this order.

1. `SPACEFAST_MCP_WORKSPACE_ROOT`, or the `--workspace-root` flag on `sf mcp`.
2. The first `file:` root your MCP client advertises. The server asks once per session and remembers the answer, so changing roots mid-session has no effect.
3. The directory the server process started in.

Setting the environment variable turns off root discovery. The variable wins and your client's advertised root is ignored.

Inside that root, `publish` refuses a few things outright.

- Absolute paths. Every `path` must be relative to the workspace root.
- Any path that escapes the root.
- Symbolic links, and anything that is not a regular file or a directory.
- Paths that look like credential material.

Some files never upload, at any depth. `.env` and every `.env.*`, `.git`, `node_modules`, `.ssh`, `.aws`, `.npmrc`, `.netrc`, `.DS_Store`, key material such as `*.pem`, `*.key`, `id_rsa`, and `.spacefast/state.json`.

Size caps are checked before any bytes are read.

| Cap | Value |
|---|---|
| Total upload | 128 MiB |
| One file | 64 MiB |
| File count | 100,000 |
| One path | 1,024 bytes |

:::warning[Anonymous publishes fail closed]
When the local runtime publishes anonymously but cannot save the Space key to `.spacefast/state.json`, the tool call fails instead of printing the credential. Fix the directory permissions and publish again.
:::
