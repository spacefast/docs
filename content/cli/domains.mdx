Find a name and buy it, then attach it to a Space. Attaching a custom domain is three API calls in one command, with DNS and TLS readiness tracked as they come up.

Every command here takes the global flags (`--api-url`, `--profile`, `--token`, `-y`/`--yes`, `--json`). The search and buying commands also take `-T`/`--team`. The rest, except `sf routing inspect`, take the space selection flags (`--space`, `-T`/`--team`, `--claim-token`). See [the CLI overview](/cli) for those.

## sf domains search

Find domain names in a conversation. A keyword checks exact matches and domain hacks. A naming brief generates ideas. Both get live availability, prices, and scores. Search never buys anything.

```text
sf domains search [QUERY] [--input <value>] [--like <value>...] [--dislike <value>...]
  [--neutral <value>...] [--select <value>...] [--unselect <value>...]
  [--interactive | --local] [--limit <number>]
```

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--input=<value>` | none | Previous search receipt, session, or request: JSON, `@file`, or `-` for stdin |
| `--like=<value>` | none | Like a saved suggestion. Repeat for more than one |
| `--dislike=<value>` | none | Dismiss a saved suggestion. Repeat for more than one |
| `--neutral=<value>` | none | Clear a saved suggestion's like or dismissal |
| `--select=<value>` / `--unselect=<value>` | none | Add a saved suggestion to the selection, or remove it |
| `--interactive` | `false` | Keep a search conversation open in the terminal |
| `--local` | `false` | Print offline name ideas, with no account and no live checks |
| `--limit=<number>` | `20` | Number of offline ideas to print with `--local` |

Feedback flags take a domain, a suggestion ID, or the result number from the saved receipt. Save `--json` output and pass it back with `--input` to continue the same search.

```bash
sf domains search "a cozy bakery in Brooklyn" --json > names.json
sf domains search "shorter, playful names" --input @names.json --like 2 --select 3 --json
```

## sf domains contacts add

Save the person or organization domains are registered to.

```text
sf domains contacts add --file <value>
```

The JSON file needs `firstName`, `lastName`, `address1`, `city`, `state`, `postalCode`, `countryCode`, `email`, and `phone`. `organization` and `address2` are optional. `sf domains contacts list` lists saved contacts, newest first.

A contact belongs to the person who saved it, so run this signed in as yourself. Team API keys can't save contacts or buy domains.

## sf domains registration purchase

Buy up to 10 apex domains with the team's saved payment method.

```text
sf domains registration purchase DOMAIN... [--contact <value> | --contact-file <value>]
  [--expect-total <value>] [--payment-token <value>]
```

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--contact=<value>` | your newest contact | Saved registrant contact ID (`dcon_...`) |
| `--contact-file=<value>` | none | JSON file with a new registrant, saved before buying |
| `--expect-total=<value>` | none | Charge the team's payment method now for exactly this total before tax, in USD (for example `10.34`) |
| `--payment-token=<value>` | none | Pay with a Stripe shared payment token (`spt_...`) from an agent wallet instead. Needs `--expect-total` |

With `--expect-total` and purchasing power (`billing:purchase` on the paying team), the payment method is charged now. Without either, nothing is charged: the output gives you the `sf purchases confirm` command, or a dashboard link for a team admin.

```bash
sf domains registration purchase example.com example.dev
sf domains registration purchase example.com --expect-total 10.34
```

One name that can't be bought refuses the whole purchase with `domain_not_purchasable`. A total that moved refuses with `purchase_total_changed`.

## sf domains registration

Show a domain's registration: status, expiry, auto-renew and the earliest day it charges, and any failure or refund.

```text
sf domains registration <domain> [--auto-renew | --no-auto-renew]
```

A paid purchase moves from `pending_payment` to `pending_registration` to `active`. Auto-renew is on by default. It charges the team's saved payment method from 30 days before expiry, and no sooner than a week after the team is told. To renew now, run `sf domains registration renew <domain>`.

```bash
sf domains registration example.com
```

## sf purchases confirm

Charge the saved payment method for a purchase that is waiting for confirmation. Needs purchasing power on the paying team, or `domains:write` when paying with `--payment-token`.

```text
sf purchases confirm <id> --expect-total <value> [--payment-token <value>]
```

`sf purchases inspect <id>` shows a purchase and `sf purchases cancel <id>` releases one nobody has charged yet.

```bash
sf purchases confirm bpi_xxxxxxxx --expect-total 10.34 --team my-team
```

## sf domains add

Attach a domain.

```text
sf domains add <hostname> [--space <value>] [--role standard|primary|redirect]
  [--redirect-to <value>] [--redirect-status 301|302|307|308] [--wait] [--wait-timeout <seconds>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `<hostname>` | Hostname to attach. Required |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--role=<standard\|primary\|redirect>` | none | How the domain behaves. `primary` makes it the Space's main address |
| `--redirect-to=<value>` | none | Destination for redirect domains. Requires `--role redirect`. Must be an absolute URL: a value with a scheme is kept as written, a bare hostname gets `https://`, and a path such as `/docs` is refused |
| `--redirect-status=<301\|302\|307\|308>` | `308` | HTTP status for redirect domains. Requires `--role redirect` |
| `--wait` / `--no-wait` | `false` | Wait until queued work finishes before returning |
| `--wait-timeout=<seconds>` | `900` | Seconds to wait for queued work. Minimum 1 |
| `--primary` | off | Make this domain the Space's primary address. Same as `--role primary` |

The command makes three calls: it creates the domain in the Space's team, attaches it to the Space with the role you asked for, and queues a DNS check.

`--wait` polls the Space's runtime until it is active with a live version, then sends a `HEAD` request to the hostname. The response must carry `x-spacefast-runtime: 1` and the live version id. Redirect-role domains skip that serve check.

```bash
sf domains add example.com --space docs
sf domains add example.com --space docs --role primary
sf domains add www.example.com --space docs --role redirect --redirect-to example.com
```

### Output

```text
Added domain example.com.
ID: dom_xxxxxxxx
Verification: pending

Configure DNS for example.com:
  A      example.com      192.0.79.157
  A      example.com      192.0.79.175
  CNAME  www.example.com  example.com

Next: `sf domains check example.com`
```

The DNS block comes from the domain's `verification.requiredRecords` and prints nothing when that list is empty.

With `--json`, `data` is `{ domain, operations: { assignment, check } }`.

### Errors

| Code | Exit | When |
| --- | --- | --- |
| `validation_error` | 2 | The Space is anonymous. Claim it before managing domains |
| `validation_error` | 2 | `--role redirect` without `--redirect-to`, or `--redirect-to` without `--role redirect` |
| `validation_error` | 2 | `--redirect-status` is not 301, 302, 307, or 308 |

## sf domains check

Check a domain.

```text
sf domains check <domain> [--space <value>] [--wait] [--wait-timeout <seconds>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `<domain>` | Domain ID or hostname. Required |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--wait` / `--no-wait` | `false` | Wait until queued work finishes before returning |
| `--wait-timeout=<seconds>` | `900` | Seconds to wait for queued work. Minimum 1 |
| `--retry-ssl` | off | Ask for a new HTTPS certificate now instead of waiting for the next scheduled attempt |

```bash
sf domains check example.com --space docs
```

### Output

```text
Checked example.com.
Verification: verified
Operation: op_xxxxxxxx
```

On `pending` or `failed` it reprints the required DNS records and tells you to rerun the check. Run `sf domains diagnostics <name>` instead to see the records it found.

## sf domains diagnostics

Inspect domain diagnostics.

```text
sf domains diagnostics <domain> [--space <value>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `<domain>` | Domain ID or hostname. Required |

No command-specific flags.

```bash
sf domains diagnostics app.example.com --space docs
```

### Output

One line per hostname, then required actions and any notices.

```text
Diagnostics for example.com:
example.com      purpose=apex  dns=ok             txt=ok        ssl=active
www.example.com  purpose=www   dns=not_configured txt=missing   ssl=missing
```

`dns` is `ok` or `not_configured`. `txt` is `ok`, `missing`, or `not_required`.

## sf domains list

List domains attached to a Space. Aliased as `sf domains ls`.

```text
sf domains list [--space <value>]
```

No arguments, no command-specific flags.

```bash
sf domains list --space docs
```

### Output

A table of `DOMAIN | VERIFICATION | KIND | LAST CHECKED`, or the line "No domains attached to this space."

## sf domains remove

Remove a domain assignment from a Space. Aliased as `sf domains rm`.

**This unassigns, it does not delete.** The command sends `{"spaceId": null}`, so the hostname stays in your team's domain inventory and can be attached to another Space. The Space pointer is cleared only after provider teardown finishes, so the record keeps pointing at the Space while it drains.

```text
sf domains remove <domain> [--space <value>] [--wait]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `<domain>` | Domain ID or hostname. Required |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--wait` / `--no-wait` | `true` | Wait until queued work finishes before returning |

This is a destructive remote action. It prompts "Remove this domain from the space?" unless you pass `-y`. In agent mode it refuses with `confirmation_required` (exit 2) until you pass `-y` explicitly.

```bash
sf domains remove example.com --space docs
```

## sf routing compute

Resolve the latest version's `_redirects` and `_headers` with current variables.

```text
sf routing compute [--space <value>]
```

No arguments, no command-specific flags.

This previews the newest finalized rule set, pending version first and live version second, and only when that version's status is `ready`.

```bash
sf routing compute --space docs
```

### Output

A `# _redirects` block, a `# _headers` block, then one `severity: file:line message` line per diagnostic. With `--json`, `data` carries `latestVersionId`, `redirects`, `headers`, `diagnostics`, `variableDependencies`, and `systemVariableDependencies`.

## sf routing inspect

Compile local `_redirects`, `_headers`, and `sf.jsonc` routing rules, and optionally match URLs against the merged result. This runs entirely on your machine. It takes no space selection flags and makes no API call.

```text
sf routing inspect [--routing <dir>] [--url <value>]
```

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--routing=<dir>` | `.` | Directory holding `_redirects`, `_headers`, and the Space config file (`spacefast.config.ts` or `sf.jsonc`) |
| `--url=<value>` | none | URL or path to match against the compiled rules. Repeatable |

```bash
sf routing inspect
sf routing inspect --routing ./dist --url /old-path
```

### Output

```text
routing: /abs/path
rules: 3 redirects, 1 header blocks
error: _redirects:4 redirect_loop_invalid This rule points back to the same path and could create a loop.
/old-path: {"status":301,"destination":"/new-path"} headers={}
```

The command sets exit code 2 when any routing diagnostic is an error.
