SPACEFAST DOCUMENTATION - IMPLEMENTED INFORMATION ARCHITECTURE

This is the complete public documentation structure. It follows the patterns
of the strongest developer-docs sites (Stripe, Vercel, Cloudflare, Railway,
Supabase) rather than internal conventions:

- Guides and generated reference are separate surfaces. The header has two
  tabs: Docs (learning and product guides) and Reference (generated and exact
  contracts). No benchmark site mixes API/CLI/error reference into the middle
  of a learning sidebar.
- The homepage is a curated hub with card groups, not just the first sidebar
  page.
- Agents are a first-class audience with their own top-level section, the way
  Railway has "Railway for Agents" and Stripe leads with agent setup. The docs
  own agent setup; the marketing site is not the canonical setup surface.
- Every page must earn its place. Pages that only described a dashboard screen
  or a single CLI flag were merged into the page where that task actually
  lives. One page per task, not one page per toggle.
- Platforms and Zero are early products. Each is documented on a single strong
  page and grows a tree only when real usage demands it.

NAMING AND STRUCTURE RULES

- Use human actions and recognizable product nouns.
- Put a page in one primary place. Cross-link it elsewhere instead of listing
  it in several sections.
- This repository is the public source of truth for documentation.
- URLs may move freely before launch. Prefer the clearest final URL over
  compatibility with an unpublished route.
- The paths below are the required public navigation. Route verification
  checks that every path appears in the sidebar and produces an indexable
  built page.

ROUTE POLICY

Authored pages use the paths above. There are no compatibility redirects for
old authored-page URLs because the documentation site has not launched.

Generated routes stay at /api/reference, /platforms/api/reference, /cli,
/errors, and /changelog. Those paths are embedded in generated artifacts and
tool output, so they keep their public contracts. In navigation they belong to
the Reference tab; because Blume scopes tabs by path prefix, routes outside
/reference show the Docs sidebar and reach the Reference surface through the
header tab.

CONTENT OWNERSHIP

All public explanatory documentation is authored in this repository. Generated
OpenAPI, CLI, error, changelog, and redirect snapshots remain producer-owned
and must be refreshed through their exporter rather than edited by hand.
