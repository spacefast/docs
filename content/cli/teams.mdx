Use `sf teams` to create or select a team and set defaults for new Spaces. Adding a member requires [Pro](/pricing); CLI credentials can list members and invitations. `sf teams members invite` sends invitations with a credential that has `teams:members.write`, such as `sf login` with Agent access. Other membership changes require the dashboard. [`sf login`](/authentication#log-the-cli-in) stores an API key, not a browser session. See [credential limits](/api-keys#what-an-agent-grant-cannot-do).

A team owns Spaces, domains, and billing. Every member holds one team role: `owner`, `admin`, or `member`. See [Teams](/teams) for the model, and [`sf share`](/cli/share) for per-Space access, which is a separate system.

Most subcommands accept `-T, --team` (slug, ID, or name; env `SPACEFAST_TEAM`). Without it they use the default team set by `sf teams switch`.

## sf teams list

List teams. Alias: `sf teams ls`.

```text
sf teams list
```

Lists teams available to the current login.

### Example

```bash
sf teams list
```

### Output

A table of `TEAM` and `ID`, with `*` marking the default team. `--json` returns `{ teams, defaultTeamId }`, each team carrying `id`, `name`, `slug`, and `role`.

## sf teams switch

Set default team.

```text
sf teams switch [TEAM]
```

Sets the default team for future CLI publishes. The selection is stored per login and cleared when you log in again. It can never outlive the identity that made it.

### Arguments

| Argument | Default | What it is |
| --- | --- | --- |
| `[team]` | prompted | Team slug, ID, or name |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `-T, --team=<value>` | none | Team slug, ID, or name, as an alternative to the positional. Env `SPACEFAST_TEAM` |

### Example

```bash
sf teams switch acme
```

### Output

`Default team: acme`. `--json` returns `{ team }`.

### Errors

| Code | Exit | What to do |
| --- | --- | --- |
| `validation_error` | 2 | No stored login. Run `sf login` first |

## sf teams create

Create a team.

```text
sf teams create NAME
```

Creates a team owned by the current login.

### Arguments

| Argument | Default | What it is |
| --- | --- | --- |
| `<name>` | required | Display name for the new team |

### Example

```bash
sf teams create "Acme Inc"
```

### Output

```text
Created team acme.
Team: team_…
```

`--json` returns `{ team }`.

## sf teams accept

Accept a team invitation.

```text
sf teams accept INVITATION
```

Accept the invitation through its join link in the dashboard. With CLI credentials, this request is refused with `403 authorization_level_not_allowed`. Once you accept in the dashboard, credentials approved for all teams can see the new team.

### Arguments

| Argument | Default | What it is |
| --- | --- | --- |
| `<invitation>` | required | Invitation ID from the invite link |

## sf teams defaults

Show who can view this team's Spaces, or set the access new Spaces start with.

```text
sf teams defaults [ACCESS] [--new-subteams private|parent_team]
```

Setting a value changes only Spaces created from now on. Existing Spaces keep their access. **Private spaces only** and **Hide from search engines** show up here but change only in the dashboard, under Team settings → Access.

### Arguments

| Argument | Default | What it is |
| --- | --- | --- |
| `[access]` | show only | `private` (your team), `parent_team` (your team plus everyone in its parent team, who can view and comment), or `public` (anyone on the web). `parent_team` is for a subteam in an Enterprise or Internal family |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--new-subteams=<private\|parent_team>` | unchanged | Root teams on Enterprise or Internal: the access new Spaces start with in each subteam created from now on. Existing subteams keep theirs |
| `-T, --team=<value>` | default team | Team slug, ID, or name. Env `SPACEFAST_TEAM` |

### Examples

```bash
sf teams defaults
sf teams defaults private
sf teams defaults parent_team --team design
sf teams defaults --new-subteams parent_team
```

### Output

```text
Private spaces only: off
Hide from search engines: off
New spaces: private
Public spaces now: 0
```

A root team with a subteam default also prints `New subteams start with:`. While **Private spaces only** is on, the last line counts the Spaces that would turn public again if it were turned off.

`--json` returns `{ teamId, defaults }`. To override the preset for one publish, pass `sf publish --access`. To change an existing Space, use [`sf share`](/cli/share).

## sf teams members invite

Invite one or more people to a team.

```text
sf teams members invite EMAIL... [--role owner|admin|member] [-T <team>]
```

Sends one invitation per address, up to 50 at a time, through [`createTeamInvitation`](/api/reference/teams/createteaminvitation). It needs a credential with `teams:members.write`, such as `sf login` with Agent access, and your team role decides which roles you can grant. Adding a member requires [Pro](/pricing).

### Arguments

| Argument | Default | What it is |
| --- | --- | --- |
| `<emails>` | required | One or more email addresses |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--role=owner\|admin\|member` | `member` | Role to grant when the invitation is accepted |
| `-T, --team=<value>` | default team | Team slug, ID, or name. Env `SPACEFAST_TEAM` |

### Example

```bash
sf teams members invite jane@example.com alex@example.com --role member
```

### Output

One address prints `Invited <email> as <role>` and the invitation ID. Several print how many people were invited. `--json` returns `{ invitation }` or `{ invitations }`.

The invitations go out together. If any fail, the command exits with the error, or with "Multiple invitation requests failed.", and doesn't list the ones that went out. Run `sf teams invitations list` to see which were sent. Sending again to an address with a pending invitation fails with `invitation_already_exists`, so a rerun only invites the addresses that failed. Resend an existing invitation from the dashboard under **Members → Pending**.

## sf teams join

`sf teams join [TEAM]` joins a team that your verified email or a pending invitation lets you into. Leave out the team to list the teams you can join.

```bash
sf teams join
sf teams join acme
```

## sf teams join-link

Print the team's join link. Only people with a verified email at one of the team's email domains can join through it. `--reset` replaces the link, and the old one stops working at once.

```bash
sf teams join-link
sf teams join-link --reset
```

## sf teams domains

Team email domains let anyone with a verified email at that domain join the team.

- `sf teams domains add DOMAIN` adds a company email domain, such as `example.com`. A current member must already have a verified email there.
- `sf teams domains list` lists the domains. Alias: `sf teams domains ls`.
- `sf teams domains remove DOMAIN` stops people at that domain from joining on their own. Current members stay. Alias: `sf teams domains rm`.

```bash
sf teams domains add example.com
sf teams domains remove example.com
```

## sf teams people

List everyone with access across a team and its subteams, one row per person: members, pending invitations, people invited to Spaces, and SSO identities. Enterprise and Internal plans only.

| Flag | Default | What it does |
| --- | --- | --- |
| `--show=<all\|members\|invited\|guests>` | everyone | Who to list. Guests have Space access but no team in this view |
| `--subteam=<value>` | none | Only people in this subteam or with access to a Space in it |
| `--search=<value>` | none | Match a name or email |
| `--outside-domains` | off | Only people with no verified address at a company domain |
| `--limit=<n>` | `20` | People per page, up to 100 |
| `--cursor=<cursor>` | none | Pagination cursor from a previous response |

```bash
sf teams people --show guests
sf teams people --subteam design --search maya
```

## sf teams sign-in inspect

Show which identity connection the team's members sign in through, the return address the identity provider must allow, and each domain with its TXT record. Owners change member sign-in in the dashboard.

```bash
sf teams sign-in inspect
```

Subteam commands (`sf teams subteams …`) are covered on [Subteams](/subteams).
