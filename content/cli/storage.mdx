List your app's stored objects and read access, edge, or runtime logs within your plan's retention window. Runtime lines take time to appear, and static Spaces have no runtime logs.

Every command here takes the global flags (`--api-url`, `--profile`, `--token`, `-y`/`--yes`, `--json`) and the space selection flags (`--space`, `-T`/`--team`, `--claim-token`). See [the CLI overview](/cli).

## sf storage

List object metadata for files uploaded by a Space's app.

This is runtime object storage, not your published files. Only a Space with a runtime app has any. Objects are addressed by a bare 32-character hex id. Each object is private or public, set when it is uploaded.

```text
sf storage [target] [--space <value>] [--limit <n>] [--cursor <value>]
```

`sf storage list` is the same command with the same flags, aliased as `sf storage ls`.

### Arguments

| Argument | What it is |
| --- | --- |
| `[target]` | Space ID, slug, live URL, or domain. Defaults to the linked Space |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--local-url=<url>` | none | Use a local `sf dev` server instead of the live version |
| `--port=<port>` | none | Local `sf dev` server port. Shorthand for `--local-url http://127.0.0.1:<port>` |
| `--limit=<n>` | `50` | Maximum objects to return. Maximum 100 |
| `--cursor=<value>` | none | Continue from the opaque cursor returned by the last page |

```bash
sf storage
sf storage docs --limit 10
sf storage list --space docs
```

### Output

A table of `Id | Size | Type | Uploaded by | Created`, or "No stored objects." A further page prints as `Next cursor: <value>`.

With `--json`, `data` is `{ objects, cursor }`. Each object carries `id`, `public`, `contentType`, `createdAt`, `filename`, `size`, `uploaderId`, `sha256`, and `url`.

To upload, use [`sf storage put`](#sf-storage-put), the API, or `storage.upload()` from the client SDK inside your app.

### Errors

| Code | Exit | When |
| --- | --- | --- |
| `validation_error` | 2 | `--limit` or `--cursor` did not parse. Raised before the request |

## sf storage delete

Force-delete an app storage object as the Space owner, regardless of who uploaded it. Aliased as `sf storage rm` and `sf storage del`.

```text
sf storage delete [id] [--space <value>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `[id]` | Object id, for example `0123456789abcdef0123456789abcdef` |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--local-url=<url>` | none | Use a local `sf dev` server instead of the live version |
| `--port=<port>` | none | Local `sf dev` server port. Shorthand for `--local-url http://127.0.0.1:<port>` |

The id must be the 32-character hex id `sf storage` lists. A path-shaped value is rejected. This is a destructive remote action, so it prompts unless you pass `-y`. Delete is idempotent: an already-gone object prints "`<id>` was already gone."

```bash
sf storage delete 0123456789abcdef0123456789abcdef --yes
```

### Output

With `--json`, `data` carries `deleted`.

## sf storage put

Upload a file to app storage. The object is private unless you pass `--public`.

```text
sf storage put <file> [--space <value>] [--public] [--content-type <type>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `<file>` | Path to a regular file. Required. Its base name becomes the object's `filename` |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--public` | off | Make the object readable by visitors |
| `--content-type=<type>` | `application/octet-stream` | The object's MIME type |
| `--local-url=<url>` | none | Use a local `sf dev` server instead of the live version |
| `--port=<port>` | none | Local `sf dev` server port. Shorthand for `--local-url http://127.0.0.1:<port>` |

```bash
sf storage put receipt.pdf --content-type application/pdf
```

### Output

`Uploaded <file>: <id> (<size> B).` With `--json`, `data` is the stored object.

## sf storage download

Download an app storage object.

```text
sf storage download <id> [--space <value>] [--output <path>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `<id>` | The 32-character object id `sf storage` lists. Required |

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--output=<path>` | the object id | Where to save the file. An existing file is never overwritten |
| `--local-url=<url>` | none | Use a local `sf dev` server instead of the live version |
| `--port=<port>` | none | Local `sf dev` server port. Shorthand for `--local-url http://127.0.0.1:<port>` |

### Output

`Downloaded <id> to <path> (<size> B).` With `--json`, `data` is `{ id, path, size }`.

## sf logs

Read a Space's logs.

`access` covers requests that reached your Space's origin. `edge` covers requests handled at the edge, cache hits included. Each edge query reads one hostname (the primary unless you pass `--hostname`), and a busy window can be truncated; see [Edge request logs](/infrastructure/edge-request-logs) for its filters and limits. With `runtime` you get what your code logged, with the request id and handler for each line. A static Space has no runtime lines.

A new line takes a while to appear, because it's written on the origin, shipped, and indexed before it can be read. **An empty page doesn't mean it's broken.** Keep paging while there's a cursor: a page can be empty even when more lines are coming.

```text
sf logs [target] [kind] [--space <value>] [--limit <n>] [-f] [--cursor <value>]
  [--request-id <value>] [--handler <value>]
```

### Arguments

| Argument | What it is |
| --- | --- |
| `[target]` | Space ID, slug, live URL, or domain. Defaults to the linked Space |
| `[kind]` | `access`, `edge`, or `runtime`. Defaults to `access` |

A bare kind in the first slot works: `sf logs runtime` is the same as `sf logs --space <linked> runtime`.

### Flags

| Flag | Default | What it does |
| --- | --- | --- |
| `--limit=<n>` | `50` | Maximum number of log entries. Minimum 1, maximum 100 |
| `-f, --follow` | `false` | Poll for new entries every 2 seconds until interrupted with Ctrl-C |
| `--cursor=<value>` | none | Continue from the cursor printed by the previous page |
| `--request-id=<value>` | none | Runtime logs only. Everything logged while serving one request |
| `--handler=<value>` | none | Runtime logs only. Lines from one Zero mutation or Functions handler |
| `--since=<iso>` | none | Start of the log window as an ISO 8601 timestamp |
| `--until=<iso>` | none | End of the log window as an ISO 8601 timestamp |
| `--wait-timeout=<seconds>` | none | With `--follow`, stop following after this many seconds and exit 0 |
| `--hostname=<value>` | none | Edge logs only. Hostname assigned to the Space |
| `--method=<value>` | any | Edge logs only. HTTP method. Repeatable |
| `--status=<code>` | any | Edge logs only. HTTP status code. Repeatable |
| `--remote-addr=<ip>` | any | Edge logs only. Client IP address. Repeatable |
| `--user-agent=<value>` | any | Edge logs only. Exact User-Agent value. Repeatable |
| `--asn=<number>` | any | Edge logs only. Autonomous system number. Repeatable |
| `--ja3-hash=<value>` | any | Edge logs only. JA3 fingerprint. Repeatable |

`--follow` polls, it does not stream over a socket. It dedupes by the whole entry and remembers up to 5,000 keys.

```bash
sf logs
sf logs runtime --follow
sf logs docs runtime
sf logs runtime --request-id req_9f21
sf logs runtime --follow --json
```

### Output

Access entries carry `timestamp`, `host`, `method`, `path`, `status`, and `bytes`. Runtime entries carry `id`, `timestamp`, `level` (`debug`, `info`, `warn`, or `error`), `requestId`, `versionId`, `handlerName`, `message`, and `metadata`.

Paged human output ends with `More: --cursor <value>` when there is another page, otherwise "Nothing logged yet." or "No requests yet."

`--follow --json` emits one JSON object per line, then a final `{"data":{"followed":true,"kind":"..."}}` when you interrupt it. That makes it safe to pipe into `jq`.

Log history is a plan limit. A request that reaches past your retention window is clamped to the effective start, with a `log_retention_clamped` warning naming it. See [limits](/limits).

### Errors

| Code | Exit | When |
| --- | --- | --- |
| `validation_error` | 2 | `kind` is not `access`, `edge`, or `runtime` |
| `validation_error` | 2 | `--request-id` or `--handler` passed with the access log |
