---
title: Roll back
description: How to roll back a Spacefast space to an earlier version.
---

Every publish creates an immutable version with its own URL. Rolling back
promotes an earlier ready version to live. There is no rebuild and no re-upload.
The site is live in seconds.

```bash
sf versions ls
```

```bash
sf rollback v12
```

Run these commands from a directory that contains `.spacefast/state.json`. Or
pass `--space docs` to target a space explicitly. Use `sf versions ls` to find
the target version.

`sf rollback <version>` is the recovery-focused command. `sf promote <version>`
uses the same backend operation. Use `sf promote` when you want to frame the
change as promotion rather than recovery. Both commands accept a version id,
ref, or number such as `ver_123`, `v12`, or `12`.

Versions and [channels](/publishing/channels) are the canonical vocabulary.
`sf deploy` is an exact alias of `sf publish`, and `sf deployments` of
`sf versions`.

## Retention and storage

Committed file bytes across versions count toward the team's storage quota. If
you reach the quota, Spacefast blocks new publishes. It never takes the live
site down. Delete old versions or add storage to free up room. Retention never
deletes the live version or a version that a channel points at. The current
rollback target is always safe.

Retention follows the team's current policy. Spacefast warns the team and offers
an export before an unreferenced version becomes eligible for removal. Spacefast
protects versions that are live or that a channel references.

## Permanent Version URLs

Each version URL serves exactly the content that you published. That content
never changes. The team's current entitlements control whether an older version
URL is public. Entitlements do not change owner access or API access. Rollback
and export continue to work.
