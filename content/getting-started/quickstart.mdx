---
title: Publish your first site
description: Hand your project to your coding agent or run one CLI command and get a live URL in seconds, no account required.
---

Publish a folder, a zip, or a single `index.html`. Spacefast gives it a stable
live URL. You do not need an account for the first publish. Your site is
live seconds after the upload completes.

## Tell your agent

The fastest path is the one you already have open. Paste this into your coding
agent:

```text
fetch https://spacefast.com/setup.md
and publish this space to Spacefast
```

The agent fetches the instructions, publishes, and reports back the live URL
and the immutable Version URL. If it published without an account, it also
hands you a claim link. To make the setup stick (CLI, skill, and MCP), see
[Set up an agent](/agents).

## Or run the CLI yourself

Install the CLI once, then publish:

```bash
curl -fsSL https://spacefast.com/install.sh | bash
```

```bash
sf publish ./dist --name docs
```

`--name` sets the space title. If Spacefast guesses your single-page-app setup
wrong, add `--spa true` to force the SPA fallback. The receipt shows the live
URL, the immutable version URL, and, without an account, a site link and a
claim link. A space starts private, so the site link is what opens it in a
browser; the bare live URL asks for access until you
[grant it](/spaces/access). The full command surface is in the
[CLI reference](/cli).

The first CLI publish writes `.spacefast/state.json` next to the folder. Later
publishes from that folder update the same space at the same URL, and each one
creates a new version. Spacefast skips unchanged files when the hashes match.
Every version is immutable, and [`sf rollback`](/publishing/channels) promotes
an earlier one with no rebuild.

## Claim your space

If you published without an account, claim the space within 6 hours: open the
claim link and sign in, or the space [expires](/publishing/anonymous). After
claiming, you keep the same URL for every future publish and get full version
history.

The claim link carries the space's only key, so treat it like a password: keep
it out of chat and screenshots. It works as many times as you need until the
deadline.

:::tip
Spacefast looks for `index.html` at the root of what you publish. It never
runs server-executable files. It serves static files only.
:::

No agent and no terminal? [spacefast.com](https://spacefast.com) has an upload
box: drag a folder, zip, or `index.html` onto it and publish. Same URLs, same
claim link.

## Try the CLI in your browser

Nothing installed yet? The
[Spacefast browser terminal](https://my.spacefast.com/terminal) gives you a
working shell and a useful slice of the `sf` CLI. It starts with a small
static site in `/workspace/site`:

```bash
cd /workspace/site
```

```bash
sf publish .
```

The receipt includes the live URL, the version, and a link to claim the space.
Run `sf --help` to explore. To manage spaces already in your account, run
`sf login`; the terminal opens the device-login page in a new tab.

It is a browser sandbox, not your computer. Commands that need local files,
installed packages, or a full operating system belong in the [real CLI](/cli).
