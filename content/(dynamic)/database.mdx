There's no connection string for this database. Your code reaches it through Zero's `db` or a worker's `env.DB`, and you reach it through a single-use SQL console.

:::note[Don't have a database yet?]
Start a [Zero](/zero-runtime) app with `sf init --runtime zero`. Its `zero.config.ts` declares the collections and tables, and Spacefast creates them when you publish. A [Functions](/functions#what-is-on-env) worker also gets the database, through `env.DB`.
:::

## What it is

Every Space has one database, the MySQL that lives on the machine serving the site. A [Zero](/zero-runtime) app keeps its collections and tables there. A [Functions](/functions) worker gets it as `env.DB`.

You do not create it, size it, or connect to it. Your config declares the schema, and Spacefast applies it when a version initializes.

:::warning[There is no external connection string]
No route, flag, or dashboard field returns a DSN. Your code reaches the database through `db` (Zero) or `env.DB` (Functions). For everything else there is the [SQL console](#the-sql-console).
:::

## Query it from code

In a Zero app, hooks and actions read and write through `db`. Your schema is the API, and its column and relation names are checked at build time.

```ts zero.config.ts
import { action, db, defineConfig, integer, table, text } from "zero";

const notes = table({
  body: text().notNull(),
  ownerId: integer().notNull(),
});

export default defineConfig({
  tables: { notes },
  actions: {
    recent: action({
      input: { ownerId: integer().notNull() },
      access: "authenticated",
      async handler({ ownerId }) {
        return await db.query.notes.findMany({
          where: { ownerId },
          orderBy: { id: "desc" },
          limit: 20,
        });
      },
    }),
    add: action({
      input: { body: text().notNull(), ownerId: integer().notNull() },
      access: "authenticated",
      async handler(input) {
        const [row] = await db.insert(notes).values(input).returning();
        return row;
      },
    }),
  },
});
```

| Call | What it does |
| --- | --- |
| `db.query.<name>.findMany({ where, orderBy, limit, offset, columns, with })` | Matching rows |
| `db.query.<name>.findFirst({ where, ... })` | One row, or `null` |
| `db.insert(table).values(row \| rows).returning()` | Inserts, and returns the new rows |
| `db.update(table).set(patch).where(filter).returning()` | Updates, and returns the changed rows |
| `db.delete(table).where(filter).returning()` | Deletes, and returns the removed rows |

`where` is an object filter: `{ col: value }`, or `{ col: { eq, ne, gt, gte, lt, lte, in, notIn, like, isNull, isNotNull } }`, with top-level `OR`, `AND`, and `NOT`. A relation key filters through the relation: `{ author: { name: "Alice" } }`. `orderBy` is `{ col: "asc" | "desc" }`. Await every call.

An action's writes run in one transaction. A throw anywhere rolls all of them back.

A Functions worker gets a D1-shaped binding instead.

```ts handler.ts
export default {
  async fetch(request: Request, env: { DB: D1Database }) {
    const { results } = await env.DB.prepare("select * from notes limit 10").all();
    return Response.json(results);
  },
};
```

## Migrations

Your `zero.config.ts` is the schema. When you publish a version that changes it, Spacefast diffs it against the schema the Space already runs and applies the difference while the new version initializes, before it can go live.

To see the SQL a change produces, build locally and read the newest file in `zero/migrations/`:

```bash
sf zero build
```

:::warning[Rollback does not roll back the schema]
Every version of a Space shares one database, migrated forward to the newest schema. Rolling back to older code keeps the newer tables and columns, so make schema changes the older code can live with.
:::

To rename a collection or table without moving its data, keep the old physical name with `storageName`:

```ts
const stockItems = table(fields, { storageName: "stock_items" });
```

A build that drops one collection or table while adding another is refused as an ambiguous replacement. Rename with `storageName` instead, and remove storage in its own change.

## The SQL console

When you need raw SQL, the CLI mints a single-use phpMyAdmin sign-in URL.

```bash
sf db console
sf db console --show-secret
```

`sf db console` opens a browser by default, because the URL grants full SQL authority over the Space's database. `--show-secret` prints it instead, and is the deliberate override. The URL is masked in `--json` receipts unless you pass it. Opening the console needs write access to the Space.

A Zero app's tables share a prefix that starts with `sfz_`.
