`sf` publishes folders and projects to Spacefast and manages versions, domains, access, data, teams, and agent tooling. Every command shares the same global flags, `--json` receipt format, and exit-code table. For every command's full arguments and flags, see the [CLI command reference](/cli/reference).

## Install

Install the npm package globally with Node.js 22.19 or newer:

```bash
npm install -g spacefast
```

The `spacefast` package installs two binaries: `spacefast` and `sf`. Standalone binaries for macOS (arm64, x64), Linux (arm64, x64), and Windows (x64) bundle their own runtime with no Node.js install required.

On macOS or Linux, install the same two binaries with Homebrew:

```bash
brew install spacefast/tap/spacefast
```

Upgrade Homebrew installs with `brew upgrade spacefast`. Verify your installation with `--version`:

```bash
sf --version
```

The output prints your installed CLI version. Add `--json` to print `{ "data": { "version": "..." } }`.

## Authentication

Sign in through your browser, verify your identity, and publish a directory:

```bash
sf login
sf whoami
sf publish ./dist
```

`sf login` prints a verification code and link to stderr, opens your browser when on a local desktop session, and polls until you approve. Only the approving device needs a browser, so `sf login` works over SSH and inside containers. The confirmation receipt prints to stdout.

To sign in without a browser, store an API key with `sf login --token <key>`. In CI pipelines, export `SPACEFAST_TOKEN` instead of running `sf login`.

- **Re-authenticating**: `sf login` stores the replacement credential before revoking the old one, so a canceled or expired login never leaves you signed out. Signing in clears your stored default team and resets it from the new identity.
- **Handoff-link protection**: passing a browser handoff URL as a command argument aborts with `handoff_link_in_argv` (exit 2) so secrets stay out of shell history and process lists.
- **Signing out**: `sf logout` clears your default team, removes the local CLI credential, and revokes CLI-minted tokens against the API URL they were issued for. It never deletes API keys you created yourself; revoke those with [`sf api-keys revoke`](/cli/reference#sf-api-keys-revoke-key).
- **Bare `sf`**: running `sf` with no subcommand runs [`sf status`](/cli/reference#sf-status), showing your identity, default team, and linked Space.

## Global flags

Every command accepts these flags, either before or after the command path (for example, `sf --json spaces list`):

| Flag | Default | What it does |
| --- | --- | --- |
| `--json`, `--no-json` | off | Print a machine receipt instead of human output, or force human output in agent mode |
| `--api-url=<url>` | resolved | Spacefast API base URL. Env `SPACEFAST_API_URL` |
| `--profile=<name>` | current profile | Named provider profile from `sf profiles`. Env `SPACEFAST_PROFILE` |
| `--token=<key>` | none | API key for non-interactive auth; prefer `SPACEFAST_TOKEN` |
| `-y, --yes` | `false` | Skip confirmation prompts. Env `SPACEFAST_YES` |
| `--cwd=<dir>` | current directory | Change working directory before the command runs, including Space resolution |
| `-d, --debug` | off | Print redacted diagnostics on stderr. Env `SPACEFAST_DEBUG` |
| `--no-color` | off | Disable terminal color. Env `NO_COLOR` |
| `--non-interactive` | off | Never prompt; fail when required inputs are missing. Env `SPACEFAST_NON_INTERACTIVE` |

Commands that act on a Space also accept `--space`, `-T, --team`, and `--claim-token`. Commands that queue background work accept `--wait`, `--no-wait`, and `--wait-timeout=<seconds>` (default `900`).

## JSON output

Pass `--json` to print `{ "data": ... }` on stdout when a command succeeds, and nothing else. Progress lines go to stderr in human mode and are suppressed under `--json`. Failures print `{ "error": ... }` on stderr, so piping stdout into a parser never turns a failure into data.

This success receipt shows the `{ data }` envelope returned by `sf whoami --json`:

```json
{
  "data": {
    "account": {
      "id": "usr_0123456789abcdef",
      "email": "dev@example.com",
      "name": "Dev Example"
    },
    "teams": [{ "id": "team_0123456789abcdef", "name": "Acme", "slug": "acme", "role": "owner" }]
  }
}
```

This error receipt shows the `{ error }` envelope printed to stderr when a credential has expired:

```json
{
  "error": {
    "code": "credential_expired",
    "message": "The credential used for this request is expired.",
    "type": "https://spacefast.com/docs/errors/credential_expired",
    "title": "Credential expired",
    "status": 401,
    "retryable": false,
    "recovery": "sf login",
    "requestId": "req_0123456789abcdef",
    "suggestions": ["Create a new API key or sign in again."]
  }
}
```

`error.code` is stable. `error.retryable` tells you whether repeating the same command unchanged could succeed. `error.recovery` gives one runnable command, and validation failures include an RFC 6901 `error.pointer`. Cursor-paginated list commands pass their `{ data, pagination }` envelope through without double-wrapping. The CLI replaces capability query parameters and secret paths with `[redacted]`.

Some commands use their own output contract instead of the CLI JSON envelope. `sf mcp` and `sf mcp proxy` speak MCP over stdio, `sf api` prints raw API responses verbatim, and `--help` prints human help unless you pass `--json`.

## Exit codes

Run `sf help exit-codes` to print this table offline:

| Code | Name | Meaning |
| --- | --- | --- |
| `0` | `ok` | Success |
| `1` | `unknown` | Unexpected or uncategorized failure |
| `2` | `validation` | Bad flags or arguments, or client/server validation failure (HTTP 422) |
| `10` | `auth` | Authentication failure: not signed in, or the credential is missing or expired (HTTP 401). Run `sf login` |
| `11` | `permission` | Signed in, but this credential or role cannot perform the action (HTTP 403). Signing in again does not help |
| `20` | `not-found` | Resource not found or gone (HTTP 404 or 410) |
| `30` | `conflict` | Request conflicts with the resource's current state (HTTP 409) |
| `40` | `network` | Network failure reaching the API before the request arrived. Retryable |
| `50` | `timeout` | Timed out waiting for queued work. Check `sf operations <id>` before retrying |
| `60` | `outcome` | A change may or may not have been applied. Inspect state before repeating |
| `130` | `cancelled` | Interrupted with Ctrl-C, or a confirmation prompt was declined |

[`sf doctor`](/cli/reference#sf-doctor) is the one exception: it exits `1` when any check fails without classifying the failure.

## Interactive, CI, and agent modes

The CLI prompts only when stdin and stderr are terminals, `--json` and `--non-interactive` are absent, and neither CI nor agent mode is active.

- **Destructive actions**: pass `--yes` (or `SPACEFAST_YES=1`) to confirm without a prompt. Without it, a non-interactive run fails with `confirmation_required` (exit 2). Declining a prompt exits `130`.
- **Agent mode**: setting `SPACEFAST_AGENT=1` (or running inside a detected agent harness such as Claude Code, Codex, Cursor, or Gemini CLI) defaults to `--json` and suppresses prompts. Pass `--no-json` or `SPACEFAST_AGENT=0` to opt out. Agent mode never implies `--yes` for remote destructive actions. Set `SPACEFAST_AGENT_ALLOW_DESTRUCTIVE=1` to auto-confirm local protection-removing actions only, such as `sf unlink`.
- **CI environments**: when `CI` (or a recognized CI runner variable) is set, the CLI runs non-interactively and masks secrets in logs, while keeping human output unless you pass `--json`.

## How the CLI resolves Space, API URL, and files

When you omit `--space`, the CLI picks a Space in this order:

1. `--space` or `SPACEFAST_SPACE`. A blank value is a validation error, never "absent", so a misconfigured CI variable cannot silently create a second Space.
2. Anonymous claim state in `.spacefast/state.json`, unless `.spacefast/space.json` names a different Space ID.
3. The `space` field in `.spacefast/space.json`.
4. The cached `spaceId` in `.spacefast/state.json`.

If nothing selects a Space and your account can reach one Space, the CLI selects it. With several, an interactive terminal prompts and a non-interactive run fails with `no_space_selected` (exit 2).

The CLI resolves the API base URL in this order:

1. `--api-url`
2. An explicit `--profile`
3. `SPACEFAST_API_URL`
4. `.spacefast/state.json`
5. `.spacefast/space.json`
6. The active profile
7. The stored login's URL
8. `https://api.spacefast.com`

Every credential is bound to the base URL it was issued for and never sent to another origin.

On macOS, the CLI stores logins in the Keychain under `Spacefast CLI`. On Linux, it uses Secret Service through `secret-tool`. On Windows, in CI, and in other environments, it writes `~/.spacefast/auth.json`. If the keyring is locked, unlock it or set `SPACEFAST_CREDENTIAL_STORE=plaintext`.

| Path | Contents |
| --- | --- |
| `~/.spacefast/config.json` | Profiles and defaults, including your default team |
| `~/.spacefast/credentials/profile-*.json` | One credential file per profile |
| `.spacefast/space.json` | Committable link: Space ID, team, and API base URL |
| `.spacefast/state.json` | Local cache and anonymous claim credentials. Never commit it; `sf` adds it to `.gitignore` |
| `spacefast.config.ts` | Typed project configuration written by `sf init`; see [Configuration](/config-file) |
| `sf.jsonc` | Permanently supported JSONC configuration; `spacefast.config.ts` takes precedence when both exist |

## Update checks and shell completion

The CLI checks npm for a newer release every 7 days and prints the upgrade command matching how you installed it. It skips update checks when you pass `--json`, run `mcp` commands, or redirect stderr away from a terminal.

The npm package includes shell completion for `zsh`, `bash`, and PowerShell. Standalone binaries and Homebrew do not include completion. Run `sf autocomplete` with your shell name:

```bash
sf autocomplete zsh
```

Add the printed setup line to `~/.zshrc`, `~/.bashrc`, or `$PROFILE`. After upgrading `sf`, refresh the cache with `sf autocomplete --refresh-cache`.

| [`sf plugins`](/cli/reference#sf-plugins) | Install the Spacefast plugin for coding agents that support plugins |
| [`sf continue`](/cli/reference#sf-continue) | Exchange a saved `sfc_` Space key for a durable API key after claim approval |

`sf mcp proxy` caps individual responses at 32 MiB and times out requests after 55 seconds. `sf mcp` restricts publish paths to the workspace root and refuses absolute paths, escaping paths, and symlinks.
