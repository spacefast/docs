Public static files use one of three default cache policies. Protected responses, conditional routing, and header overrides change that. To get a fresh response from the edge, republish.

## Default policies

Public static files use these defaults unless a header override or a [no-cache rule](#responses-that-are-never-cached) applies.

| Policy | `Cache-Control` |
| --- | --- |
| Immutable | `public, max-age=31536000, immutable` |
| HTML | `public, s-maxage=600, max-age=0, must-revalidate` |
| Every other file | `public, s-maxage=86400, max-age=0, must-revalidate` |

In the last two, `max-age=0` makes the browser revalidate on every load, and the ETag turns that revalidation into a 304 when nothing changed. Shared caches keep HTML for ten minutes and other files for a day. A visitor's browser never serves a stale page from its own cache. Visitors see a new publish as soon as the shared copy refreshes.

**HTML always gets the ten-minute policy**, so a missed purge never leaves a page stale for long.

## Which files are immutable

A file gets the one-year immutable policy when either of these is true.

**Its name carries a content hash.** Detection is strict, so a file with a version number or date in its name isn't cached for a year by mistake.

| Filename | Immutable | Why |
| --- | --- | --- |
| `app.3f9c2d1a4b5e6f70.js` | Yes | A hex digest with both letters and digits |
| `index-DiwrgTda.js` | Yes | A chunk id with an uppercase and a lowercase character |
| `jquery-3.7.1.min.js` | No | A version number, not a digest |
| `photo_20240115.jpg` | No | A date |
| `hero-image1.jpg` | No | A counter |

**Or it sits under a known build output directory** and is not `.html`, `.htm`, `.php`, `.txt` or `.xml`. Those directories are `_next/static/`, `_app/immutable/`, `_nuxt/`, `_astro/`, and `_spacefast/platform/`.

Outside those directories, a file with an unhashed name gets the one-day shared policy. That works, but hashed filenames make repeat visits faster.

A precompressed sidecar such as `app.js.gz` is served at its own literal URL and is never selected as the answer for `app.js`.

## Overriding the policy

A `Cache-Control` header rule that matches a file wins, and its value is sent verbatim:

```text _headers
/data/*.json
  Cache-Control: public, max-age=60
```

Publish warns with `header_cache_control_platform_managed`, because the header you set applies to browser responses while shared caching stays managed. Full rules for header files are on [Redirects, rewrites, and headers](/routing).

## Responses that are never cached

| Response | `Cache-Control` |
| --- | --- |
| Anything on a protected Space, or served to an admitted visitor | `private, no-store` |
| Any URL carrying a share-link token in `?__=` | `private, no-store` |
| Any request that is not `GET` or `HEAD` | `private, no-store` |
| Any URL a conditional routing rule touches | `no-store` |
| The 405 page | `no-store` |

The non-GET rule has no exceptions. The shared cache in front of a Space keys on host, path, and query and ignores the method, so a cached answer to a `POST` could be replayed to a `GET`.

## Vary is not part of the cache key

The edge keys a stored response on **host, path, and query**. It does not read `Vary`.

Because of this, a routing rule with a `Country=`, `Language=`, `Cookie=`, or `Agent=` condition could send one visitor's response to the next visitor. To prevent that, any URL a conditional rule touches is `no-store` for everyone, whether the condition matched or not.

If a page needs to differ by country, language, or client, give each variant its own URL instead of putting a condition on one URL. Then every variant can be cached.

## What a publish does

Activating a new version points the Space's hostnames at it and purges the edge for every hostname the Space serves. Purges clear a **whole hostname**. You can't purge one URL, because the cache key includes the query string and a purge can't list every query a page might be requested with.

Immutable version hostnames aren't purged, because their content never changes.

A purge can fail. If it does, HTML still refreshes within ten minutes and other files within a day, when the shared copy expires.

Browsers don't need a purge. `max-age=0` makes every navigation revalidate, so a returning visitor gets the new version on their first request after the shared copy refreshes. Hashed files and files under the build output directories above are cached for a year. A new build gives changed hashed files new names, but an unhashed file in one of those directories keeps its URL, so browsers can keep the old copy. Rename it when its content changes.

## Getting a fresh response

<Steps>
  <Step title="Republish">
    A publish purges every serving hostname. This is usually all you need.
  </Step>
  <Step title="Check which version answered">
    Every response carries `X-Spacefast-Runtime: 1`, and `X-Spacefast-Version` names the version that answered.

    ```bash
    curl -sI https://my-site.space.fast/ | grep -i x-spacefast
    ```
  </Step>
  <Step title="Bypass the shared copy while you compare">
    Add a unique query parameter. The query is part of the cache key, so `?cachebust=1` is a different entry.

    ```bash
    curl -sI "https://my-site.space.fast/?cachebust=$(date +%s)"
    ```
  </Step>
  <Step title="Open the version URL">
    Each retained, ready version has a fixed hostname that serves its exact build, regardless of what is live. See [URLs and hostnames](/urls).
  </Step>
</Steps>

## Validators

An `ETag` is sent on every 200. Its value is derived from the file's content, not from a clock, so republishing identical bytes produces the same tag.

Conditional requests are answered by the edge, not by the origin, so a revalidation that finds nothing changed comes back as a 304 without reaching your files. Static responses carry no `Last-Modified`.
