Connectors let your team connect an external service once—an OpenAPI spec, a GraphQL endpoint, or a remote MCP server—and call its tools from AI agents, Space pages, Functions, and scripts. Credentials stay sealed in Spacefast and never enter prompts, source code, or browsers.

Connectors are in Public Beta on Go, Pro, and Enterprise plans. A team on Personal (Free) gets `feature_unavailable`. Enterprise adds team-wide connector allowlists, blocklists, and site-serving controls.

## How Connectors work

Four building blocks cover everything Connectors do:

| Concept | What it is |
| --- | --- |
| **Connector** | A tool source your team registers once (from the catalog or by pasting any URL). Its slug becomes the tool namespace, such as `hubspot` or `linear`. |
| **Connection** | One authenticated account (`cxn_…`) on a connector, owned by the **Team** (shared) or **Personal** (only yours within this team). |
| **Policy** | Rules that decide whether a tool call **Runs freely** (`approve`), **Asks first** (`require_approval`), or is **Blocked** (`block`). |
| **Role** | A Space-level declaration in `spacefast.config.ts` or `sf.jsonc` that exposes chosen tools to a Space's pages and Functions. See [Connectors in Spaces](/space-connectors). |

## Three ways to use a connector

| Surface | Best for | How it runs |
| --- | --- | --- |
| **AI agents (On-Device MCP)** | Letting Claude Code, Cursor, Codex, or Claude Desktop search and call your team's tools | `sf mcp` exposes one gateway tool, `search_connector_tools`, under your team's policy and approval rules. Hosted MCP and `sf mcp proxy` intentionally omit connector tools. See [MCP server](/agents/mcp-server). |
| **Space pages and Functions** | Showing live data or running actions on a Space with no backend to write | Declare a role, bind an account, and call `space.connectors.<role>.<tool>()` or `env.CONNECTORS`. See [Connectors in Spaces](/space-connectors). |
| **CLI and API** | Scripts, CI jobs, or testing a single call | Run one tool or a multi-tool sandbox program with `sf connectors run` or `POST /v1/connectors/runs`. See [sf connectors](/cli/connectors) and the [connectors API](/api/connectors). |

## Who can do what

- **Team owners and admins** manage connectors in the dashboard: registering tool sources, connecting or disconnecting team accounts, and editing team policy rules (`connectors:write`).
- **Team members** can list and run team connections through the API, CLI, and On-Device MCP (`connectors:read` and `connectors:execute`), subject to team policy rules and any per-credential connection limits. The team's **Connectors** dashboard pages remain owner and admin only.
- **API keys** need connector scopes: `connectors:read` reads connectors, connections, tools, rules, and runs; `connectors:write` manages connectors, accounts, and rules; `connectors:execute` runs tools. `write` and `execute` each include `read`, and neither includes the other. See [API keys](/api-keys).

## Quickstart

<Steps>
  <Step title="Add a connector">
    Open **Connectors** in the team sidebar, click **Browse Connectors**, and click **Add** on a catalog row—or paste any API or MCP URL and click **Detect**. From the terminal:

    ```bash
    sf connectors search linear
    sf connectors create linear
    ```
  </Step>
  <Step title="Connect an account">
    Open the connector, click **Connect Account**, pick **Team** or **Personal**, and finish OAuth sign-in or enter the required API key. From the terminal:

    ```bash
    sf connectors connections connect linear
    ```
  </Step>
  <Step title="Set policy rules">
    Open **Policies** in the connectors header to decide which tools run freely, ask a person first, or stay blocked:

    ```bash
    sf connectors policies add '*' --action require_approval
    sf connectors policies explain cxn_abc123/issues.list
    ```
  </Step>
  <Step title="Call a tool">
    Try it from the **Tools** page, from the CLI, or from a local agent connected to `sf mcp`:

    ```bash
    sf connectors run --tool cxn_abc123/issues.list --args '{"limit":5}'
    ```
  </Step>
</Steps>

The dashboard pages live under **Connectors** in the team sidebar. A switch in the header moves between **Connectors**, **Runs**, and **Policies**.

## Add a connector

### From the catalog

The catalog lists curated presets, the public registry, and your team's own connectors. It has one row per source type, so a service with an API and an MCP server appears as two rows.

1. Open **Connectors** in the team sidebar and click **Browse Connectors**.
2. Search, or filter by **All**, **API**, **GraphQL**, or **MCP**.
3. Click **Add** on the row you want.

The row changes to **View** once added. A row that needs a provider-specific endpoint shows **Set Up** and opens the add form.

### From any URL

Paste any URL a service published. Detection inspects it, so the endpoint it registers can differ from the URL you pasted.

1. On **Browse**, paste the URL into the search box and click **Detect**.
2. Click **Add Connector** on the candidate you want.
3. Check **Name**, **Namespace**, and **Description**, then click **Register**.

**Namespace** is the connector slug: lowercase letters, digits, and dashes, starting with a letter or digit. Agents read **Description** when choosing between connectors. You enter no credentials here; authentication comes from the source, and Spacefast asks remote MCP servers how they authenticate.

```bash
sf connectors detect https://api.example.com
sf connectors create https://api.example.com/openapi.json
```

## Connect an account

1. On **Connectors**, open a connector row and click **Connect Account**.
2. Under **Who can use it**, choose **Team** or **Personal**.
3. If the connector offers more than one auth method, pick one under **Method**.
4. Optional: add a **Label** so agents can tell accounts apart when a connector has more than one.
5. Click **Connect**.

**Team** shares the account with the team and agents acting for it. **Personal** keeps it yours, only within this team. API keys can connect **Team** accounts only.

Connecting ends in one of three states:

| Result | What to do |
| --- | --- |
| `connected` | Ready to use |
| `authorization_required` | Complete OAuth sign-in at the provider (`Open Sign-In` in the dashboard, or open the printed URL from the CLI). The callback finishes the connection automatically |
| `input_required` | Provide the fields the connector asks for and connect again. Provider setup notes and links appear inline (or via [`getConnectorCredentialGuidance`](/api/reference/connectors/getconnectorcredentialguidance)) |

```bash
sf connectors connections connect stripe --api-key "$STRIPE_KEY"
sf connectors connections connect linear --owner personal
```

A tool address is `<connectionId>/<tool>`. While a connector has one usable account, `<connector>/<tool>` also works. Adding a second account turns the short form into `connection_ambiguous`, so address tools by connection id.

## Policy rules and approvals

A policy rule pairs an address pattern with an action:

| Pattern | Matches |
| --- | --- |
| `*` | Every tool |
| `<connector>/*` | Every tool on every account of one connector |
| `<connector>/<tool>` | One tool on every account of one connector |
| `<connectionId>/*` | Every tool of one account |
| `<connectionId>/<tool>` | One tool on one account |

| Action | Dashboard label | When an agent or tool call matches |
| --- | --- | --- |
| `approve` | **Runs freely** | Runs immediately |
| `require_approval` | **Ask first** | Parks until a person approves or denies it |
| `block` | **Blocked** | Fails with `connector_tool_blocked` |

How rules combine:

- **Most specific pattern wins.** Spacefast evaluates rules by specificity, not creation order.
- **Team rules are a floor.** A **Personal** rule can tighten a **Team** rule, never loosen it.
- **Unmatched tools use the source's own default.** A tool can also ask for approval itself.
- **Pattern and owner are fixed.** To change either, delete the rule and add a new one. Deleting a block hands its tools back to the next matching rule.

Add rules on **Policies** in the connectors header (an API key can add **Team** rules only), or check what an address resolves to without calling it:

```bash
sf connectors policies add '*' --action require_approval
sf connectors policies explain cxn_abc123/charges.create
```

On Enterprise plans, team owners and admins can also set a team-wide connector allowlist or blocklist and restrict which connectors may serve Spaces.

### Decide a parked run

A parked run returns an `approvalUrl` and appears in two dashboard views:

- **Approvals**, under **Connector calls awaiting approval**.
- **Runs**, filtered to **Waiting on you**. Click **Review** to inspect the matched rule, arguments, and deadline before approving, or click **Deny** on the row.

**Approve** runs the call once. **Deny** fails it with `connector_tool_blocked`. A parked run expires after 15 minutes.

Approvals require a signed-in person. A CLI login or API key trying to approve fails with `human_approval_required`; read back a person's decision with `sf connectors run inspect` or `sf connectors run resume <runId>`. Pass `--deny-unattended` on `sf connectors run` to fail immediately with `connector_approval_required` instead of parking.

## Find and run tools

Click **See tools** on a connector row (or open **Connector tools** from the command palette) to browse every reachable tool, its summary, resolved policy effect, input schema, and source-declared safety (**Read-only**, **Writes**, or **Destructive**). Open any tool to run it directly from a form or JSON payload.

From the CLI, inspect a connector or connection, then run a single tool or a sandboxed program:

```bash
sf connectors inspect hubspot --query deals
sf connectors connections inspect cxn_abc123
sf connectors run --tool cxn_abc123/issues.list --args '{"limit":5}'
```

| Status | Meaning |
| --- | --- |
| `running` | Still working. Check again with `sf connectors run inspect` |
| `awaiting_approval` | Parked on a person's decision |
| `succeeded` | Finished. Output is in `result` |
| `failed` | Finished with an RFC 9457 problem document in `error` |
| `expired` | Parked past 15 minutes without a decision |

`sf connectors run` waits up to 30 seconds by default (`--wait` up to 120 seconds) and exits `1` on `failed` or `expired`.

## Limit which connections a key or app can use

By default, a credential with connector scopes reaches every team connection it is allowed to use. Narrow it to specific connections when a script, CI job, or AI client should touch only one account:

- **API keys:** Pass `--connection <connectionId>` (repeatable) on `sf api-keys create` or `sf api-keys update`, or pass `connectorAccess: { connectionIds: ["cxn_abc123"] }` over the API. Remove the limit with `--all-connections` or `connectorAccess: null`. See [API keys](/api-keys#limit-connector-access).
- **OAuth apps and CLI logins:** Open **Choose Connections** on the consent screen, or edit the allowlist later on **Connected apps** without re-authorizing.

A connection outside a credential's allowlist answers `404` as if it doesn't exist.

## Keep connections working and clean up

Open a connector's **Accounts** tab for connection actions:

| Action | What it does | CLI |
| --- | --- | --- |
| **Edit…** | Changes **Label** and the agent note, **What it's for** | `sf connectors connections update` |
| **Check Health** | Probes the provider without changing state | `sf connectors connections health` |
| **Re-Sync Tools** | Re-reads the tool list so added or removed tools show up | `sf connectors connections refresh` |
| **Reconnect…** | Re-authenticates or replaces a key while keeping the id, label, policies, and Space bindings | `sf connectors connections reconnect` |
| **Disconnect…** | Purges the stored credential permanently | `sf connectors connections disconnect` |

Token refresh happens automatically; reconnect only when a connection reports `needs_reauth` or `degraded`, or to rotate an API key. A disconnected account cannot be reconnected—connect again to create a new connection id.

### When a member leaves

Before removing a team member, the dashboard shows their connector dependencies:

- **Personal connections** owned by that member disconnect automatically on removal. Stored credentials are purged, pending sign-ins are canceled, and any Space bindings pointing to them are removed.
- **Team connections** the departing member created stay active, listed during removal so an owner or admin can reconnect them with a team-owned account or rebind affected Spaces if needed.

### Remove a connector

```bash
sf connectors delete linear --yes
```

Deleting a connector disconnects every account on it, then deletes the connector and its tools. Built-in connectors cannot be removed.
