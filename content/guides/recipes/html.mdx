---
title: Plain HTML
description: Publish a folder of HTML, CSS, and images with no build step and no package manager
---

A folder of HTML, CSS, images, and fonts publishes as it sits on disk. No toolchain, no config file.

## What to build

Nothing. Write `index.html` and put the assets next to it.

```text
my-space/
  index.html
  about.html
  styles.css
  logo.svg
```

## The output directory

The folder itself. There is no build output to find, so you hand `sf publish` the directory you wrote.

## Publish

```bash
sf publish ./my-space
```

A single file works too. `sf publish ./index.html` sends one file and serves it at `/index.html`.

## What the receipt shows

```text
Published: https://quiet-harbor.space.fast

  Open          https://quiet-harbor.space.fast
  Live URL      https://quiet-harbor.space.fast
  Version URL   https://quiet-harbor--v1.space.fast
  Version       v1 (ready)
  Files         4
```

`about.html` answers `/about`, and `/about.html` redirects there, because clean URLs are on by default. To add custom redirects, rewrites, or response headers, declare them in `spacefast.config.ts` (see [Redirects and rewrites](/redirects) and [Response headers](/headers)); `_redirects` and `_headers` files also work as optional migration conveniences.

## The gotcha

`sf publish` decides between "upload this" and "build this" from the file names in the folder. A `package.json`, a lockfile, or a framework config file sitting next to your `index.html` flips it to the build path. Then it installs dependencies and looks for a build command you may not have.

Force the upload path:

```bash
sf publish ./my-space --prebuilt
```

The same rule applies to a `.zip`. An archive publishes as static files when it holds an `index.html` and none of those build markers.

Full detection rules are on [Frameworks and builds](/guides/frameworks).
