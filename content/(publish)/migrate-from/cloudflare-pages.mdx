---
title: Move from Cloudflare Pages
description: Publish a Cloudflare Pages site on Spacefast. _redirects and _headers publish as they are, wrangler.toml build settings are read, and Pages Functions move to Spacefast Functions
---

Your `_redirects` and `_headers` files publish with your pages, and Spacefast reads `wrangler.toml`. A Pages Functions folder usually needs only a check against Spacefast's routing rules.

## Move the site

<Steps>
  <Step title="Publish the project">
    Run `sf publish` in the project and let Spacefast build it, or publish the output folder you deploy today.

    ```bash
    sf publish
    ```

    To build on every push instead, connect the repository with [Publish from Git](/git).
  </Step>
  <Step title="Bring the environment variables">
    Export the project's variables as a dotenv file, then import it.

    ```bash
    sf env import .env --from cloudflare
    ```

    Variables are write-only by default. See [Environment variables](/environment-variables).
  </Step>
  <Step title="Check your functions">
    Compare your `functions/` folder with the [Functions file router](/functions#the-functions-file-router) before you rely on it. See the next section.
  </Step>
  <Step title="Point your domain">
    Add the domain to the Space and add the DNS records it asks for. Spacefast issues the certificate once DNS points at it. Keep the Pages project up until the new address answers. See [Custom domains](/domains).
  </Step>
</Steps>

## What carries over

| From Cloudflare Pages | On Spacefast |
| --- | --- |
| `_redirects` and `_headers` files | Published with your pages and applied as routing rules |
| `wrangler.toml` build settings | Read after framework detection, and they override the detected build command and output directory |
| Redirects and headers in `wrangler.toml` | Converted to `_redirects` and `_headers` rules |
| Environment variables | Imported from a dotenv export with `sf env import --from cloudflare` |

Rule order, conditions, and limits are on [Redirects, rewrites, and headers](/routing).

## Functions

Spacefast [Functions](/functions) detects two layouts Pages users already know:

- **A `functions/` folder** is a file router. A module's file name is its route, and the HTTP methods it exports are the methods it answers. `functions/haiku/[topic].ts` answers `/haiku/:topic`.
- **A root `handler.ts`** default-exports an object with a `fetch` method, the shape Workers expects, and answers the whole site.

Each handler gets standard `Request` and `Response` objects, with no Spacefast wrapper. The Space's database is on `env.DB`, a D1-shaped binding. Check the [Functions](/functions) page for what each file answers and for the outbound `fetch()` rules.

## What doesn't

- **`cloudflare-cdn-cache-control`** and the other CDN-specific cache headers are rejected with `header_cdn_cache_unsupported`. Spacefast manages shared caching; `Cache-Control` still applies to browsers. See [Caching](/caching).
- **`_routes.json`** and the `.wrangler` folder are dropped at publish. See [what gets uploaded](/publish#what-gets-uploaded).
- **Features Spacefast cannot convert** are flagged at publish. Move them to a supported equivalent, or pass `--allow-unsupported-platform-features` to publish without them.

## Choose who can open it

A team's new Spaces start private unless the team changed its default. Make the Space public, or share it with a link, in [Spacefast Share](/share).
