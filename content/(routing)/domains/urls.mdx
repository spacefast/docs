Adding a custom domain leaves the Space's managed hostname in place. A later slug rename moves that address and redirects the old one.

## The default hostname

Every new Space gets a hostname as soon as it is created:

```text
https://{label}.space.fast/
```

The label comes from the Space slug, lowercased, with every character outside `a-z`, `0-9`, and `-` replaced by `-`, runs of hyphens collapsed, and a 63-character cap. A new Space with slug `my-space` serves at `https://my-space.space.fast/`.

Adding a custom domain never retires the managed hostname.

Existing Spaces on `view.fast` keep that domain. Publishing again, renaming the slug, or creating a version or branch preview keeps the Space on its original domain. Existing version URLs and share links keep working.

A hostname label stays taken across both domains. If `my-space.view.fast` belongs to a Space, another Space cannot take `my-space.space.fast`.

A slug cannot contain `--`, because `--` is the separator between a version or branch label and the Space label in the hostnames below.

## Version URLs

Every version that reaches ready gets a fixed hostname of its own:

```text
https://{label}--v{number}.{apex}/
```

The apex is the Space's original domain, either `space.fast` or `view.fast`. Version 7 of a new Space named `my-space` is `https://my-space--v7.space.fast/`. The URL is computed once when the version turns ready and stored on the version row. It survives a slug rename and serves that build while the version is retained. [Deleting a version](/versions#how-many-versions-are-kept) stops its hostname from serving.

Existing URLs such as `https://v7--my-space.view.fast/` retain their format. Use the returned `immutableUrl` rather than composing a version URL yourself.

The API and the CLI report it as `immutableUrl`, with an `immutableUrlStatus` of `pending` until the hostname is routable.

Version hostnames always send `X-Robots-Tag: noindex, nofollow`, and their `/robots.txt` blocks all crawlers, even if you published your own `robots.txt`. Search engines index the live hostname, not the versions.

## Branch preview URLs

A version published from a connected Git branch also gets a branch hostname:

```text
https://{label}--br-{alias}.{apex}/
```

The apex stays the same as the Space's default hostname. Existing branch URLs such as `https://br-preview--my-space.view.fast/` retain their format.

The alias is cut to 16 characters. A branch hostname follows the branch, so each push points the same URL at the newer version. Branch hostnames are also noindex.

## What the live URL points at

The publish receipt, the CLI, and the dashboard all report the live URL as `liveUrl`:

| Space state | `liveUrl` |
| --- | --- |
| No custom domain | The Space's default hostname |
| Primary domain, state `active` | `https://{primary hostname}/` |
| Primary domain still verifying, or blocked | The Space's default hostname |

It always uses `https` and ends the root with a trailing slash. A primary domain does not replace the default hostname until it is `active`, so Spacefast never reports a link to a domain that is not serving yet.

## After a custom domain becomes primary

Both hostnames keep serving. The only change is the URL Spacefast reports for the Space.

You cannot turn off the managed hostname. Share the custom domain instead.

The apex and `www` pair is different. When one of them serves, the other gets an automatic 308 to it. See [Custom domains](/domains).

## Renaming a Space

Renaming the slug moves the default hostname to the new label on the same domain. A `view.fast` Space stays on `view.fast`. A `space.fast` Space stays on `space.fast`. The old hostname redirects to the new one with a temporary 307 that keeps the path and query, so links you already shared still work. Branch hostnames under the old label get the same 307.

Version URLs do not change when you rename a Space.

## Share links

A share link is the page you want with the secret in the query string:

```text
https://my-space.space.fast/docs?__=sfl_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

At the current hostname, one request returns that page with no redirect or interstitial, so `curl` and agents get the same page a browser does. Creating, scoping, and revoking them is on [Spacefast Share](/share).

## Hostnames you cannot claim

Any hostname ending in `.space.fast` or `.view.fast` is refused as a custom domain with [`domain_reserved_suffix`](/errors/domain_reserved_suffix). Default hostnames pass DNS verification automatically, so allowing them as custom domains would let one team claim another team's address.

## Hostnames that do not serve

A request to a hostname Spacefast does not route, or to a Space that has never published, answers `404` with `Cache-Control: no-store` and the body `This space hasn't been published yet.` The response includes `X-Spacefast-Undeployed: 1`. Use that header or the body to tell an unpublished Space apart from a missing page on a published one. A Space removed under the strictest safety category sends the same response, so the header alone does not prove the Space was never published.
