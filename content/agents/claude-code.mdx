The Spacefast plugin lets Claude Code publish your project and manage resources within its approved permissions. Team membership and billing changes still need you in the dashboard.

## Install

```bash
claude plugin marketplace add spacefast/plugins
claude plugin install spacefast@spacefast
```

The plugin does not assume the `sf` CLI is installed. You sign in the first time the hosted server is used, through your client's OAuth flow.

Two other lanes exist. `npx -y plugins add spacefast/plugins -t claude-code -y` installs the same plugin. `sf setup agent --agent claude-code` writes MCP config into `~/.claude.json` and installs the skill into `~/.claude/skills/spacefast/` instead. See [sf setup agent](/agents/sf-setup).

## What the plugin adds

### MCP server

One entry, the hosted server.

```json .mcp.json
{
  "mcpServers": {
    "spacefast": {
      "type": "http",
      "url": "https://mcp.spacefast.com"
    }
  }
}
```

Claude Code stores the OAuth credential for it. The `"type": "http"` field is required. Claude Code rejects a bare `{ "url": ... }` entry.

The plugin doesn't add the local stdio server. If you need it to read folders on your machine, set it up separately with [sf setup agent](/agents/sf-setup).

### Skills

The base skill, `skills/spacefast/`, routes each request to the right tool and sets the publish-poll-report loop. Task skills cover building a site, editing a Space, sharing, custom domains, fixing a deployment, and the Design System. Each skill is a `SKILL.md` plus a `references.md`. See [skills](/agents/skills).

### Hooks

```json hooks.json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume|clear|compact",
        "hooks": [
          {
            "type": "command",
            "command": "node \"${GROK_PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}/hooks/session-start.mjs\""
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "^(Bash|PowerShell|exec_command|shell_command|mcp__(?:plugin_spacefast(?:[-_]local)?_)?spacefast(?:[-_]local)?__(?:publish|createPublish|createSpaceBuild|retryBuild|finalizeSpaceVersion|promoteSpaceVersion|commitSpaceSourceWorkspaceChanges))$",
        "hooks": [
          {
            "type": "command",
            "command": "node \"${GROK_PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}/hooks/design-reminder.mjs\"",
            "timeout": 5
          }
        ]
      }
    ]
  }
}
```

The `SessionStart` script reads `.spacefast/space.json` in your working directory. If that file names a Space, it writes this line into the session, followed by a reminder to check the team's Design System before publishing.

```text
Spacefast project detected. This directory is linked to <space> at <liveUrl>. Use the Spacefast skill and preserve .spacefast/space.json. Treat .spacefast/state.json as credential material: never print, commit, or archive it.
```

The live URL is appended only when it starts with `https://`. If the file is missing or holds no Space, the hook prints nothing.

The `PreToolUse` script adds the same Design System reminder before a Spacefast publish, build, or promote tool call, or before a shell command that runs `sf`. It's advisory and never blocks the call. Neither hook makes network calls or sends telemetry.

## Verify it works

Ask the agent to call `searchDocs` for a documentation query, then `getDocsPage` with a returned slug before attempting a publish.

<Prompt description="Use the Spacefast MCP server to search the docs for custom domains." actions={["copy"]}>
Use the Spacefast MCP server to search the docs for custom domains.
</Prompt>

If the tools are wired up, Claude Code names the tool it called. Then try a publish.

<Prompt description="Publish this folder to Spacefast and give me the live URL." actions={["copy"]}>
Publish this folder to Spacefast and give me the live URL.
</Prompt>

The hosted server needs a signed-in connection, so the plugin can't publish anonymously. To publish without an account, use `sf publish`, which returns a claim link. See [Publish without an account](/anonymous-and-claim).
