The Spacefast plugin lets Cursor publish your project and call API operation tools, within the permissions you approved. Some actions remain reserved for a signed-in person.

## Install

```bash
npx -y plugins add spacefast/plugins -t cursor -y
```

You can also run `sf setup agent --agent cursor`. It writes `~/.cursor/mcp.json` and installs the skill into `~/.cursor/skills/spacefast/`, or into `<project>/.agents/skills/` with `--project`.

## What the plugin adds

### MCP server

```json .mcp.json
{
  "mcpServers": {
    "spacefast": {
      "type": "http",
      "url": "https://mcp.spacefast.com"
    }
  }
}
```

This is the hosted server. Complete the browser OAuth flow when Cursor prompts you. It has no filesystem, so `publish` takes inline files, and anonymous publishing goes through `sf publish` instead.

### A rule and skills

The plugin ships the Spacefast skills plus a `rules/spacefast.mdc` rule.

```md rules/spacefast.mdc
---
description: "Build and publish websites, edit existing Spaces, manage sharing and domains, and apply saved team standards with Spacefast. Use the installed task skill for the requested workflow."
globs:
alwaysApply: false
---
```

`alwaysApply: false` means Cursor pulls the rule in when the description matches what you asked for, rather than adding it to every request. The body is the same routing guidance the base skill carries. See [skills](/agents/skills).

## Manual config

Put this in `~/.cursor/mcp.json` to add the hosted server without the plugin.

```json ~/.cursor/mcp.json
{
  "mcpServers": {
    "spacefast": {
      "type": "http",
      "url": "https://mcp.spacefast.com"
    }
  }
}
```

The `"type"` field is required; omitting it breaks the config.

Writing this file by hand or through the CLI keeps every other top-level key intact, but it drops comments. The CLI refuses to write through a symlinked config.
