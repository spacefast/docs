A publish sends a directory or a single file to a space. A publish that
changes the content creates an immutable [version](/publish/versions) with
its own URL. A publish with identical content is a no-op. Earlier versions
stay available for [rollback](/publish/versions).

Directory publishes preserve relative paths and can carry `_redirects`,
`_headers`, and [`sf.jsonc`](/serve/settings), so serving rules ship with
the files they describe. Spacefast serves everything as inert static
content; request-time code runs only through a declared [Zero](/zero) or
[Functions](/functions) runtime. The CLI and dashboard warn you early about
files that the runtime safety policy blocks.

New spaces are private by default. The publish receipt returns an Open link
that grants access, and [access settings](/share) make the space public when
you are ready.

## Ways to publish

| Path                  | Best for                                                     |
| --------------------- | ------------------------------------------------------------ |
| `sf publish ./dist`   | Local projects, agents, incremental updates                  |
| `sf publish --remote` | [Building in the cloud without Git](/publish/remote)         |
| `POST /v1/publish`    | One-shot HTTP from scripts (see [API](/api))                 |
| Dashboard Drop        | No tooling at hand, zip or `index.html`                      |

The [CLI](/cli) is the main path. It handles incremental uploads, `--json`
receipts, CI, and dry runs. It is also what [agents](/agents) run for you,
and what the [quickstart](/start) uses. The same publish is one HTTP call:

<CodeGroup>

```bash CLI
sf publish ./dist
```

```bash curl
curl -F archive=@site.zip https://api.spacefast.com/v1/publish
```

</CodeGroup>

Add `--space docs` to target a space explicitly, `--json` for a
machine-readable receipt, or `--dry-run` to preview the upload without
publishing.

Drop is the dashboard uploader. Drag a
folder, a zip archive, or a standalone `index.html` onto a space and
publish. Interrupted uploads resume, and Spacefast expands zip archives
before publishing. Unless you want a file listing, put `index.html` at the
archive root. During a browser upload, keep the tab open until the upload
hands off to the server. To publish this way without an account, use
[drop.website](https://drop.website); the upload creates an
[anonymous space](/publish/anonymous) with a claim link.

## What serves the homepage

The space mode decides:

- Website mode, the default, serves root `index.html` as the homepage when
  it is present. Turn on the SPA fallback (`--spa true`) to route unmatched
  paths to it.
- Files mode serves a browsable file tree and does not support SPA
  fallback.

## What never serves

Configuration travels with the publish but is not content. `sf.jsonc`,
`_redirects`, `_headers`, `theme.json`, `_layout.html`, and `_pages/` are
compile inputs, and requesting one returns 404. Files and directories whose
names start with a dot are private too. The one exception is a root
`.well-known/` directory, which publishes normally so that verification
files and discovery manifests work.

## First publish and updates

The first publish creates a space and saves the space reference locally in
`.spacefast/state.json`. Later publishes update that space, or the one named
with `--space`. Updates compare `sha256` and size against the current
version, so unchanged files are never uploaded again. When the upload
finishes, the [live channel](/publish/versions) moves to the new version
atomically.

A few flags shape what an update creates:

- `--publish-mode` replaces the whole site (`snapshot`, the default) or
  adds to what is already deployed (`additive`).
- In snapshot mode, `--immutable-asset-prefix /assets/` names a path prefix
  whose files are content-addressed and kept from the previous version, so
  a tab loaded before the deploy can still fetch its chunks.
- `--config-only` publishes a config-only version that carries the prior
  artifact forward without building or uploading content.
- `-m "Rework the nav"` records a plain-language changelog entry for the
  version, shown in version history in place of the detected git commit
  message.

Publishes and builds draw from the team's resolved capacity, and CLI pushes
and CI builds count the same.

## Content scanning

Spacefast scans published content for malware and abusive material. While a
scan finishes, a publish can be held briefly and surfaces as
[`scan_pending`](/errors/scan_pending). A scan that finds malware blocks
the publish with [`malware_detected`](/errors/malware_detected).

Takedowns remove serving for abusive content, and affected requests return
[`abuse_takedown`](/errors/abuse_takedown). You can report abusive sites
through the API; see the [API reference](/api/reference).
