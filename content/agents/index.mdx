## Coding agents, plugins, and MCP

For coding agents that work with local folders and repositories, install the **Spacefast plugin** first — it sets up MCP, Spacefast skills, and advisory hooks in one step.

<CardGroup cols={3}>
  <Card title="Spacefast plugin" icon="package">

  </Card>
  <Card title="npx spacefast setup" icon="terminal">

  </Card>
  <Card title="Direct MCP" icon="plug">

### Spacefast plugin (recommended)

Best for coding agents. Claude Code, Codex, and Factory Droid each take the same repository:

```bash
claude plugin marketplace add spacefast/plugins
claude plugin install spacefast@spacefast
```

Or use the universal installer for `claude-code`, `codex`, `cursor`, `vscode`, `github-copilot`, `grok`, and `kimi`:

```bash
npx -y plugins add spacefast/plugins -t cursor -y
```

In Codex on your computer, installing the Spacefast plugin (`codex plugin marketplace add spacefast/plugins && codex plugin add spacefast@spacefast` or `npx -y plugins add spacefast/plugins -t codex -y`) sets up local MCP alongside hosted MCP and skills. Nothing assumes the `sf` CLI is already installed.

### Terminal setup (`npx spacefast setup` and `sf setup agent`)

Best when you want one interactive command to sign in and configure detected agents, or when your editor lacks native OAuth and needs the `sf mcp proxy` CLI login bridge.

```bash
npx -y spacefast setup
```

To configure agent tooling alone with the installed CLI, run `sf setup agent`. See [sf setup agent](/agents/sf-setup) for every flag.

## What an agent can do

Agents call API operations directly through MCP, within the permissions you approve. Some actions, including team membership and billing changes, need you in the dashboard.

Use `publish` for files, `operation_status` for an active publish, and Space Apps for visual inspection. Call operation tools such as `searchDocs`, `getDocsPage`, and `listSpaces` directly. Continue a saved approval with `resume_execution`.

The [MCP reference](/agents/mcp-server#the-tools) links the current tool catalog and explains the runtime differences. Read the operation schema before calling it, and check a write with a read before reporting success.

If your team has a saved [Design System](/design-system), your agent can read its standards and files while working on a project. Ask it to apply the system to a new build or bring an existing project into line with the current rules.
