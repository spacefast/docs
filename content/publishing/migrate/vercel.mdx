---
title: Vercel
description: How to move a static site from Vercel to Spacefast.
---

Spacefast fits Vercel projects that build into static files. The Git workflow
carries over: [connect the repo](/publishing/git) for branch previews,
pull-request comments, and status checks. Check the target team's
routing entitlements in the dashboard before relying on external proxies.

Before switching DNS, audit the project for Vercel-only behavior. If the site
depends on request-time rendering, functions, middleware, Incremental Static
Regeneration (ISR), or Vercel image optimization, move those features first.
Use static generation, a separate backend, or a third-party service.

## Static Next.js export

For Next.js, use static export. Next.js 14 and newer versions do not have
`next export`. `next build` writes the static artifact when you configure
`output: "export"`. See the [Next.js integration](/publishing/frameworks/nextjs)
for image handling and publish setup.

```ts
// next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  output: "export",
};

export default nextConfig;
```

```bash
npm run build
```

```bash
sf publish ./out
```

## What carries over

- Framework output that is static files and runs without a Node.js server.
- Next.js pages generated by [static export](/publishing/frameworks/nextjs),
  including App Router static routes and Pages Router routes that use
  `getStaticProps` and `getStaticPaths`.
- Static assets, generated HTML, client-side JavaScript, single-page app (SPA)
  fallbacks, and custom 404 pages.
- Redirect, rewrite, and supported response-header intent after conversion from
  `vercel.json`. Vercel password protection maps to
  [Spacefast sharing](/spaces/access), not `_headers`.

## What to change

- Convert `vercel.json` redirects and rewrites into root `_redirects`. External
  rewrites become absolute-URL `200` proxy rules. They require the corresponding
  entitlement.
- Convert `vercel.json` headers into root `_headers`.
- Replace server-only framework features with static generation, external APIs,
  or client code before publishing.
- Move Vercel environment variables into the system that builds the static
  artifact: the Spacefast build settings if you
  [connect the repo](/publishing/git), or your own CI. After a publish, only
  values that the build embeds or exposes to browser code are available.

## Next.js images

Vercel's default `next/image` optimization endpoint is request-time
infrastructure. Static export requires unoptimized images, pre-generated
responsive assets, or a custom image loader.

Use the [Next.js integration](/publishing/frameworks/nextjs) to configure
static export and send public images through `i0.wp.com`. For transform limits
and advanced options, see [Image acceleration](/spaces/image-acceleration).

## What does not run on Spacefast

These Vercel and Next.js features need removal, build-time precomputation, or
another service:

- Request-time compute does not execute: Vercel Functions, Edge Functions,
  Middleware, Cron Jobs, serverless API routes, server-side rendering (SSR),
  `getServerSideProps`, Draft Mode, ISR with on-demand revalidation, and
  dynamic rendering from cookies or headers.
- Next.js static export drops API Routes, default Image Optimization (including
  the `/_next/image` and `/_vercel/image` endpoints), internationalized
  routing, framework rewrites, redirects, headers, and `getStaticPaths` with
  `fallback: true` or `fallback: "blocking"`. Recreate routing and headers with
  Spacefast `_redirects` and `_headers`; serve images with the
  [Next.js Site Accelerator loader](/publishing/frameworks/nextjs),
  `unoptimized`, or pre-generated responsive assets.
- Vercel platform products (analytics, storage, edge config, firewall and
  protection rules) and Vercel-managed environment variables do not transfer.
  The workflow around them does: [connect the repo](/publishing/git) and
  Spacefast builds on every push. `sf git connect --platform-preset vercel`
  imports build settings from your existing Vercel config.
