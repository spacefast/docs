title: Publish without an account
description: Publish by upload or Git push with no account, then claim the space before it expires.
---

Publishing without an API key creates an anonymous space. The response
includes the space key (`sfc_...`), an Open link that serves the space, a
claim link, and an expiration time. Save them immediately, because
Spacefast returns the key and links only once.

Claim the space within 6 hours or it expires. Each successful anonymous
update resets the deadline to 6 hours out, capped at 30 days after the
space creation date. Opening the claim page with a valid link extends the
current deadline toward one hour from that visit, and those extensions
total at most 6 hours.

There are two anonymous paths: a direct publish (the CLI,
`POST /v1/publish`, or a drag onto [drop.website](https://drop.website)),
and a Git push through [push.new](#publish-with-a-git-push) with nothing to
install.

## Before you claim

An unclaimed space works, with limits:

- Unclaimed spaces are private by default. The Open link from the publish
  receipt serves the space and its permanent version URLs, while the bare
  live URL shows an unclaimed notice until you claim the space or make it
  public.
- The local `.spacefast/state.json` lets the CLI keep updating the
  anonymous space.
- Static assets, redirects, response headers, SPA fallback, and metadata
  all publish.
- Anonymous spaces allow 50 MB per file, 100 MB and 1,000 files per
  version, and 20 publishes per hour per IP.
- Spacefast accepts and scans uploads like any publish, but unclaimed
  spaces serve web content only: text, images, fonts, JSON (including web
  manifests), XML (including RSS and Atom feeds), JavaScript, and gzip.
  Spacefast stores other files and serves them after you claim the space.
- External proxy execution and custom domains are not available on
  anonymous spaces.

## Publish with a Git push

[push.new](https://push.new) turns a Git push into a live site, with no
Spacefast CLI and no account:

<Steps>
  <Step title="Open push.new">
    Open [push.new](https://push.new) in your browser.
  </Step>
  <Step title="Add the remote">
    Copy the `git remote add` command shown there and run it inside the
    repository you want to publish.
  </Step>
  <Step title="Push">Push your current commit.</Step>
</Steps>

The commands look like this, but use the signed remote from your own
session:

```bash
git remote add pushnew "https://signed-remote.example"
```

```bash
git push pushnew HEAD:main
```

The status page follows the publish, shows the live URL when it finishes,
and gives you a link to keep the anonymous space in your account.

:::warning[Keep the generated remote private]
The signed Git remote is a temporary credential. Do not paste it into chat,
logs, documentation, or a committed Git configuration. When you are done,
remove it with `git remote remove pushnew`.
:::

Spacefast detects the project, runs a supported static build when needed,
and publishes the resulting files; a repository that already contains an
`index.html` publishes without a build step. The status page shows build and
publish logs. If detection chooses the wrong root or output directory, use
[build settings](/publish/git) with a saved space instead.

## What claiming unlocks

Accounts are WordPress.com accounts. Claiming moves the space into a team
and unlocks:

- Custom domains and diagnostics.
- Any proxy-route entitlement attached to the team.
- Larger file-size limits and additional routing capacity.
- Team access, billing, and long-term retention.

From the directory you published from, sign in and claim:

```bash
sf login
```

```bash
sf spaces claim --team my-team
```

Run [`sf continue`](/cli#sf-continue) to continue publishing after the
claim.

## If a space expires

When an unclaimed space reaches its deadline, Spacefast disables it. Live
access stops, the content enters a 7-day claim-only recovery window, and
deletion is queued after that window. Claiming during the window restores
the space. To restore a space you deleted yourself, call
`POST /v1/spaces/{spaceId}/restore` with its space key. The hostname serves an expired page
from then on and is never re-issued to someone else, so nobody can take
over stale links.
