title: Astro
description: Add @spacefast/astro for redirect and header parity in dev, routing validation, and merged _redirects and _headers files in the build output.
---

Spacefast publishes ordinary Astro static output without a framework-specific
host adapter. Build the site, then run `sf publish dist`. Any `_redirects` and
`_headers` files you place in the project or `public/` directory ship with
that build without configuration changes. The optional `@spacefast/astro`
integration validates those files, applies the resulting redirects and
response headers in the `astro dev` server, and emits the merged files into
the build output.

Rewrites and proxy rules fall through to Astro's own dev server, which renders
the route it knows; the platform applies them once the version is published.
[`@spacefast/vite-plugin`](/guides/frameworks/vite) serves all four locally, so
that is the one to reach for when you want a dev server that answers exactly
like production.

## Install the integration

```package-install
npm install -D @spacefast/astro
```

## Add the integration to astro.config

```ts
import { defineConfig } from "astro/config";
import spacefastAstro from "@spacefast/astro";

export default defineConfig({
  integrations: [
    spacefastAstro({
      mode: "static",
      redirects: ["/old /new 301"],
      headers: "/*\n  x-frame-options: DENY",
    }),
  ],
});
```

The integration reads `_redirects` and `_headers` from the project root, the
Astro `publicDir`, and an optional `publishDir`, then merges in the inline
`redirects` and `headers` options. Routing compile errors fail the build
unless you set `failOnRoutingError: false`.

Keep `mode: "static"` (the default) for prerendered or ordinary static sites.
Use `mode: "spa"` when client-rendered routes need an index fallback, the same
behavior as the [Vite plugin](/guides/frameworks/vite)'s SPA mode.

## Publish and inspect

```bash
sf publish dist
```

Or let [Git builds](/publish/git) detect the Astro project. Before you
upload, confirm that a declared redirect resolves as expected:

```bash
sf routing inspect --routing dist --url /old
```

For `sf publish --dry-run` output and the full list of rule sources, see
[the Vite page](/guides/frameworks/vite). For the `_redirects` and `_headers`
file syntax, see [Redirects](/serve/redirects) and [Headers](/serve/headers).
