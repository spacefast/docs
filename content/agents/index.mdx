Connect your coding agent to Spacefast once, then ask it to publish. This page covers what an agent can reach, the three connection lanes, and which one to pick.

## What an agent can do

Anything you can do in the dashboard, an agent can do over MCP. The Spacefast MCP server registers nine tools.

Six are typed tools for the jobs agents do all day.

- `publish` uploads a folder, a file, an archive, or inline files and returns the live URL and the immutable version URL.
- `operation_status` polls a publish that is still running.
- `show_space_deployments` reads deployment history and build status.
- `show_space_domains` reads domains, DNS records, and TLS status.
- `show_space_analytics` reads traffic over a 48h, 7d, or 30d window.
- `search_docs` searches the Spacefast documentation and works without a credential.

The other three cover everything else. `execute` runs one JavaScript program in a sandbox against the whole Spacefast API catalog, so teams, access rules, rollback, domain changes, and claim continuation need no dedicated tool. `skills` returns the guide for writing those programs. `resume_execution` continues a program that paused for your approval.

## Three ways to connect

  <Card title="Vendor plugin" icon="package">
    Your client's own marketplace installs MCP config, the Spacefast skill, and any hooks in one step.
  </Card>
  <Card title="Universal installer" icon="download">
    One `npx` command that writes the same plugin into any of seven supported clients.
  </Card>
  <Card title="sf setup agent" icon="terminal">
    The CLI detects your installed clients, writes MCP config, and installs the skill.
  </Card>
</CardGroup>

### Vendor plugin

Best when your client has a plugin marketplace. Claude Code, Codex, and Factory Droid each take the same repository.

```bash
claude plugin marketplace add spacefast/plugins
claude plugin install spacefast@spacefast
```

You get MCP config, the `spacefast` skill, and for Claude Code one SessionStart hook. Nothing assumes the `sf` CLI is installed.

### Universal plugins installer

Best when your client has no marketplace of its own but does read plugin directories. Targets are `claude-code`, `cursor`, `codex`, `github-copilot`, `vscode`, `grok`, and `kimi`.

```bash
npx -y plugins add spacefast/plugins -t cursor -y
```

### sf setup agent

Best when you already use the `sf` CLI and want the connection to ride on your CLI login instead of an editor OAuth flow. It detects installed clients, writes each one's MCP config, and installs the skill.

```bash
npm install -g spacefast
```

```bash
sf setup agent
```

The default connection method is `remote-proxy`, which points your client at `sf mcp proxy`. See [sf setup agent](/agents/sf-setup) for every flag.
