---
title: Next.js
description: Build a Next.js app with the bundled Spacefast adapter, or publish a static export from an older Next
---

Next.js is detected by its `next` or `nextra` dependency.

## What to build

The default `next build`. On Next 16.4, the CLI first points Next at the bundled `@spacefast/next-adapter` through the `NEXT_ADAPTER_PATH` environment variable, so there is nothing to add to `next.config`. The adapter opts the build into immutable static assets and writes down what Next produced for the classifier to read.

## Supported Next versions

| Next.js | Server-rendered build | `output: "export"` |
| --- | --- | --- |
| 16.4.5 and later 16.4 releases | Yes, through the bundled adapter | Yes |
| 15.5.29 and later 15.5 releases | Yes | Yes |

Every other release is refused, including canary and other prerelease versions. Older floors are refused because they have published security advisories.

## The output directory

`out`.

## Publish

```bash
sf publish
```

## What the receipt shows

```text
Published: https://quiet-harbor.space.fast

  Live URL      https://quiet-harbor.space.fast
  Version URL   https://quiet-harbor--v3.space.fast
  Version       v3 (ready)
  Files         212
```

## The gotcha

A refused version fails with this code:

```text
next_version_unsupported
```

It stops before anything builds and exits with code 2. On an unsupported version, do the export yourself and upload it:

```js next.config.js
module.exports = { output: "export" };
```

```bash
npx next build
sf publish ./out --prebuilt
```

One related failure mode on Next 16.4. If a custom build command runs `next build` in a way that loses the environment the CLI set, the adapter never runs. The publish then stops with `build_failed`, saying `.spacefast/next-build.json` was not written. Let the CLI invoke the build, or pass its environment through your wrapper.
