description: Publish a static Next.js export, or run SSR and route handlers with Functions and OpenNext.

Publish a static export when you can. When the app needs SSR, Route Handlers,
or Middleware, build it with OpenNext and publish the result as a Spacefast
Function.

## Static export

Configure Next.js with `output: "export"` (see the
[Next.js static export guide](https://nextjs.org/docs/pages/guides/static-exports)).
`next build` writes the static site to `out`.

```ts
// next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  output: "export",
};

export default nextConfig;
```

Set `trailingSlash: true` if you want `/about/index.html` instead of
`/about.html`.

Build and publish the generated directory:

```bash
bun run build
sf publish ./out
```

Static export works best when you know all routes at build time. Avoid
server-only features such as API Routes, Middleware, `getServerSideProps`,
ISR, and request-time redirects and rewrites. Two of these have static
answers: redirects and rewrites move to [`_redirects`](/serve/redirects), and
API calls can target your backend directly or through a
[proxy route](/serve/redirects#proxy-routes).

## Functions with OpenNext

Use this path when the app needs request-time Next.js features. Remove
`output: "export"` from `next.config.ts`; OpenNext builds the Next.js server
into a worker instead. OpenNext's Cloudflare adapter uses the Node.js runtime,
so also remove any `export const runtime = "edge"` declarations.

Then publish:

```bash
sf publish
```

Spacefast detects the Next.js project, builds it with a pinned OpenNext
Cloudflare adapter, and publishes the worker with the generated static assets.
No adapter install, no `open-next.config.ts`, no extra package script. Keep an
`open-next.config.ts` only when you need to override the defaults; Spacefast
preserves yours. Confirm the plan before anything uploads with
`sf publish --dry-run`.

Requests for a published file are served from disk first; SSR, Route Handlers,
and other misses reach the worker. You can pin the detected entry explicitly:

```jsonc
{
  "$schema": "https://spacefast.com/schemas/sf.json",
  "runtime": {
    "kind": "functions",
    "entry": ".open-next/worker.js",
  },
}
```

See OpenNext's [Cloudflare adapter setup](https://opennext.js.org/cloudflare/get-started)
for framework-specific requirements; Spacefast owns the publish step, so that
guide's Cloudflare deployment and binding configuration does not apply here.

## Image optimization

Next.js default image optimization requires a Next.js server at runtime;
static export needs `images.unoptimized`, pre-generated responsive assets, or
a custom loader (see the Next.js
[static export image optimization section](https://nextjs.org/docs/pages/guides/static-exports#image-optimization)).

For public images, use the [Site Accelerator API](/serve/images).
It transforms images through `i0.wp.com`, handling width, quality, crop, fit,
filters, and metadata at the CDN layer.

Install the shared image package:

```bash
bun add @spacefast/image
```

```ts
// next.config.ts
import { createRequire } from "node:module";
import type { NextConfig } from "next";
import { spacefastNextImageConfig } from "@spacefast/image/next";

const require = createRequire(import.meta.url);

const nextConfig: NextConfig = {
  output: "export",
  images: {
    ...spacefastNextImageConfig,
    loaderFile: require.resolve("@spacefast/image/next-loader"),
  },
};

export default nextConfig;
```

`spacefastNextImageConfig` includes the shared `loader: "custom"` and
`qualities` settings; resolve `@spacefast/image/next-loader` from your own
`next.config.ts` so pnpm, Yarn PnP, and hoisted workspaces locate the package.

Use absolute public image URLs for images that should go through Site
Accelerator. Spacefast emits relative images in `public/` as static files, and
the loader returns them unchanged.

```tsx
import Image from "next/image";

export function HeroImage() {
  return (
    <Image
      src="https://example.com/uploads/hero.jpg"
      alt="Hero image"
      width={1200}
      height={630}
      quality={85}
      priority
    />
  );
}
```

This outputs image URLs like:

```text
https://i0.wp.com/example.com/uploads/hero.jpg?quality=85&strip=all&w=1200
```

For per-component control, pass `spacefastNextImageLoader` from
`@spacefast/image/next` as the `loader` prop. For advanced Site Accelerator
options, see [Image acceleration](/serve/images), and put them in
one URL helper so components do not rebuild image URLs differently.

## Publishing checklist

- For a static export, check that `next build` creates an `out` directory with `index.html` at the root.
- For Functions, check that the OpenNext build creates `.open-next/worker.js`.
- Replace request-time features when you publish a static export. Keep them when you use Functions.
- Put `_redirects` and `_headers` in the exported output if the space needs
  Spacefast routing or response headers.
- Use Site Accelerator URLs only for public images that the CDN can fetch.
