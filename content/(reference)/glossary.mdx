Core terms used across the Spacefast documentation, with links to the guides that explain each one in detail.

## Ability

A named, schema-backed WordPress operation that a Space's runtime publishes for clients, agents, and scripts to discover and call at `/wp-json/wp-abilities/v1/abilities/<name>/run`. Platform Abilities ship with every Space, and SpacePress exports your app's queries, mutations, and collections as Abilities. See [WordPress and Content API](/wordpress).

## Action

A server-side `query()` or `mutation()` handler in `sp/` (or declared under `app.actions` in `spacefast.config.ts`) that runs on your Space's backend with typed validation, access rules, and optional rate limits. See [Actions, queries, and jobs](/actions).

## Build

The step that turns project source code into publishable output. You can build locally with `sf build` or let Spacefast build remotely from a connected Git repository. See [Frameworks](/guides/frameworks).

## Capsule

The compiled server bundle of a legacy Zero 0.8 application. `sf publish` compiles Zero TypeScript server code into a capsule that installs onto the Space alongside its database. See [Migrating from Zero 0.8](/zero-migration).

## Channel

A named pointer from a Space to one ready version. `live` is the production channel that your default hostname and custom domains follow, using either `auto` or `manual` promotion. Connected Git branches also maintain branch preview URLs that track the latest version on each branch. See [Channels and previews](/channels) and [Versions](/versions).

## Claim / claiming

Attaching an anonymous Space (published without an account) to a Spacefast account and team, which removes its expiry countdown and unlocks full serving capabilities. See [Anonymous publish and claiming](/agents/anonymous-and-claim).

## Collection

A structured content type declared under `app.collections` in `spacefast.config.ts` (or `spacepress.config.ts`), backed by your Space's database with typed fields and access rules. See [Collections](/collections).

## Drop

The drag-and-drop publish flow at [drop.fast](https://drop.fast): drag a folder, a `.zip`, or a single `index.html` into the browser to publish with no install and no account required. See [Publishing](/publish#publish).

## Functions

The runtime that runs a [Worker](#worker) alongside your Space's static files, supporting npm packages, framework server output (including OpenNext Next.js), and outbound HTTP. See [Functions](/functions).

## Grant

One rule in a Space's access list naming an audience (`public`, `team`, a named person, a share link, a password, a machine credential, or an external identity), a role, route patterns, and a target. Grants are additive; a Space with no matching Grants is private. See [Share and access](/share).

## Live (the live channel)

The production [channel](#channel) that selects the version served at a Space's live URL and custom domains. Promoting or rolling back repoints `live` at a retained, ready version without rebuilding. Moving `live` to an older version applies your current rewrites by default, which creates a new version from that version's files. Preview publishes and manual promotion policies leave `live` unchanged. See [Versions](/versions).

## Poppy

The Personal Agent Protocol (`Poppy 1.0`) supported by Spacefast so personal agents can authenticate with OAuth, discover supported tasks and skills, and sign an agent browser into a scoped dashboard session using the `poppy:browser-sign-in` scope. See [Poppy](/agents/poppy).

## Space

A container for versions, domains, data, and access settings, served at its own hostname. A Space can exist before anything is published. Custom domains belong to a team and are assigned to a Space. See [Spaces](/spaces).

## SpacePress

The full-stack TypeScript app framework built into every Space. SpacePress compiles collections, SQL tables, typed ORM queries, server actions, background jobs, TSX pages, `"use client"` interactive islands, Markdown sync, and WooCommerce stores into native WordPress and PHP with no Node.js server in production. See [Build on a Space](/build) and [Collections and CMS](/collections).

## Team

The owner of Spaces, domains, API keys, and billing in a self-serve account, even when you are the only member. Partner API integrations can use external principals for customer ownership instead. See [Teams and members](/teams).

## Traffic Rules

Edge firewall and cache-bypass rules declared under `firewall` and `cache.bypass` in `spacefast.config.ts` or in Space settings. Traffic Rules block, challenge, or bypass cache for requests matching attributes such as path, IP, country, headers, cookies, or query parameters before they reach the Space. See [Redirects and rewrites](/redirects).

## Version

An immutable snapshot created when a publish changes files or configuration. Every ready version gets its own immutable URL, which serves that exact snapshot while the version is retained. The [live](#live-the-live-channel) channel points to the version visitors see; it is empty before the first publish. See [Versions](/versions).

## Worker

The compiled JavaScript server code run by [Functions](#functions) in an isolated runtime beside a Space's static files. Static assets serve directly from the Space, while a Worker handles the dynamic routes it claims, with access to `env.DB`, storage, connectors, and outbound `fetch()`. See [Functions](/functions).

## Zero

The earlier transactional app runtime that compiles TypeScript tables, queries, mutations, actions, and HTTP endpoints into a [capsule](#capsule) paired with a MySQL database. New apps declare `collections` and `actions` directly in `spacefast.config.ts` or use [Functions](#functions). See [Migrating from Zero 0.8](/zero-migration).
